# Incident inc063

**Status:** Escalated to the owner of raw.customer. Nothing was changed.

## What broke

- `model.tpch_warehouse.stg_customers` error: Compilation Error in model stg_customers (models/staging/stg_customers.sql)

## Diagnosis

- **Started at:** `source.raw.customer`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `dim_customers`, `fct_daily_revenue`, `fct_orders`, `stg_customers`

**Evidence**

The stg_customers model failed contract validation because column account_balance is defined as VARCHAR (selected directly from raw.customer.c_acctbal) while the staging contract expects DECIMAL(15,2). The raw source column c_acctbal is VARCHAR, and profiling shows it is not losslessly convertible to DECIMAL(15,2) (missing second decimal digit). This type/format change in the source data broke the contract, so the issue originates upstream in raw.customer. No downstream dbt model change can safely recover the missing precision, so the incident must be escalated to the source owner.

**Column profile** `raw.customer.c_acctbal` (varchar to decimal(15,2)): would lose data: values arrive with at most 1 decimal places where the contract keeps 2; the missing digits can't be recovered

## What was done

No change was made to the warehouse. The data has to be corrected where it comes from.
