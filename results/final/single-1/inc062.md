# Incident inc062

**Status:** Escalated to the owner of raw.orders. Nothing was changed.

## What broke

- `model.tpch_warehouse.stg_orders` error: Compilation Error in model stg_orders (models/staging/stg_orders.sql)

## Diagnosis

- **Started at:** `source.raw.orders`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`, `stg_orders`

**Evidence**

The stg_orders model failed contract validation because its order_date column is defined as DATE in the contract but the source raw.orders.o_orderdate column is VARCHAR. Profiling shows 600 out of 15,000 rows contain values (e.g., "unknown") that cannot be converted to DATE, making the conversion lossy. According to team policy, a type/format change can only be patched if lossless, which is not the case here. Therefore the issue originates in the raw source data, and the appropriate response is to escalate to the source owner.

**Column profile** `raw.orders.o_orderdate` (varchar to date): would lose data: 600 values do not convert to date

## What was done

No change was made to the warehouse. The data has to be corrected where it comes from.

- [ ] Confirm the problem with the owner of `raw.orders`.
- [ ] Re-run `dbt build` once the source is corrected; the alarms should clear.
- [ ] Until then, treat these models as unreliable: fct_daily_revenue, fct_orders, stg_orders.
