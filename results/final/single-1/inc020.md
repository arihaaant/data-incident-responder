# Incident inc020

**Status:** Escalated to the owner of raw.orders. Nothing was changed.

## What broke

- `not_null_stg_orders_order_date` fail (750 rows): Got 750 results, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.orders`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`, `stg_orders`

**Evidence**

The not_null_stg_orders_order_date check failed with 750 rows. Querying raw.orders shows 15000 total rows, 14250 non‑null o_orderdate values, and 750 null o_orderdate values. Since the nulls exist in the source table, the issue originates upstream; the staging model simply propagates the source column, so the problem must be fixed at the source.

```sql
SELECT COUNT(*) AS total, COUNT(o_orderdate) AS not_null, COUNT(*)-COUNT(o_orderdate) AS nulls FROM raw.orders;
```

</details>

## What was done

No change was made to the warehouse. The data has to be corrected where it comes from.
