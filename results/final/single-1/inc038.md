## What broke

- `unique_stg_customers_customer_key` fail (225 rows): Got 225 results, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.customer`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `dim_customers`, `fct_daily_revenue`, `fct_orders`, `stg_customers`

**Evidence**

The unique test on stg_customers.customer_key failed with 225 duplicate rows. Raw.customer contains duplicate c_custkey values (e.g., c_custkey=6 appears twice with identical column values). Adding SELECT DISTINCT in the staging model removes the duplicate rows, making the unique test pass while preserving all data. The issue originates from duplicate rows in the source raw.customer table.
