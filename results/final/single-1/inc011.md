# Incident inc011

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `model.tpch_warehouse.stg_lineitem` error: Runtime Error in model stg_lineitem (models/staging/stg_lineitem.sql)

## Diagnosis

- **Started at:** `model.stg_lineitem`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`

**Evidence**

The stg_lineitem model failed with a Binder Error because it attempted to multiply a VARCHAR column (l_extendedprice) with a DECIMAL, which is not allowed. Profiling of raw.lineitem.l_extendedprice shows it can be losslessly cast to DECIMAL(15,2). Adding explicit casts to decimal for l_extendedprice (both in the extended_price column and the net_revenue calculation) resolves the type mismatch, and a test build with the patch passes all checks.

**Column profile** `raw.lineitem.l_extendedprice` (varchar to decimal(15,2)): converts without loss

## What was done

Proposed a change to `models/staging/stg_lineitem.sql`. The stg_lineitem model failed with a Binder Error because it attempted to multiply a VARCHAR column (l_extendedprice) with a DECIMAL, which is not allowed. Profiling of raw.lineitem.l_extendedprice shows it can be losslessly cast to DECIMAL(15,2). Adding explicit casts to decimal for l_extendedprice (both in the extended_price column and the net_revenue calculation) resolves the type mismatch, and a test build with the patch passes all checks.
