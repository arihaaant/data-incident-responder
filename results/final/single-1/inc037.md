# Incident inc037

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `unique_stg_customers_customer_key` fail (75 rows): Got 75 results, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.customer`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `dim_customers`, `fct_daily_revenue`, `fct_orders`, `stg_customers`

**Evidence**

The unique_stg_customers_customer_key test failed with 75 duplicate rows. Raw.customer contains duplicate c_custkey values (e.g., key 16 appears twice with identical data). The staging model stg_customers directly selects from raw.customer, so duplicates propagate downstream, causing the unique test to fail. Adding SELECT DISTINCT in the staging model removes the duplicate rows, which resolves the test failure (verified with try_patch). The problem originates from duplicate source rows, so the cause is upstream_data and the root node is source.raw.customer.
