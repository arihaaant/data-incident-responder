# Incident inc018

**Status:** Escalated to the owner of raw.lineitem. Nothing was changed.

## What broke

- `not_null_stg_lineitem_extended_price` fail (8751 rows): Got 8751 results, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.lineitem`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`, `stg_lineitem`

**Evidence**

The failing test not_null_stg_lineitem_extended_price reports 8751 null values in stg_lineitem.extended_price. The staging model stg_lineitem directly maps raw.lineitem.l_extendedprice to extended_price without transformation. Querying raw.lineitem shows 8751 nulls out of 60175 rows (SELECT COUNT(*) total, SUM(CASE WHEN l_extendedprice IS NULL THEN 1 ELSE 0 END) nulls). Therefore the nulls originate in the source raw.lineitem table, indicating upstream data issue. No code change can recover missing values, so the incident must be escalated to the source owner.

```sql
SELECT COUNT(*) AS total, COUNT(extended_price) AS not_null FROM raw.lineitem
```
```sql
SELECT COUNT(*) AS total, SUM(CASE WHEN l_extendedprice IS NULL THEN 1 ELSE 0 END) AS nulls FROM raw.lineitem
```

</details>

## What was done

No change was made to the warehouse. The data has to be corrected where it comes from.
