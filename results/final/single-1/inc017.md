# Incident inc017

**Status:** Escalated to the owner of raw.orders. Nothing was changed.

## What broke

- `not_null_stg_orders_customer_key` fail (1500 rows): Got 1500 results, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.orders`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`, `stg_orders`

**Evidence**

The not_null_stg_orders_customer_key test failed with 1500 rows. In raw.orders, the o_custkey column has 1500 null values out of 15000 rows (SELECT COUNT(*) AS total_rows, COUNT(o_custkey) AS non_null, COUNT(*) - COUNT(o_custkey) AS nulls FROM raw.orders). The staging model stg_orders directly maps o_custkey to customer_key without transformation, so the nulls propagate, causing the test failure. The issue originates in the source data, not in model code.

```sql
SELECT COUNT(*) AS total_rows, COUNT(customer_key) AS non_null FROM raw.orders
```
```sql
SELECT COUNT(*) AS total_rows, COUNT(o_custkey) AS non_null, COUNT(*) - COUNT(o_custkey) AS nulls FROM raw.orders
```

</details>

## What was done

No change was made to the warehouse. The data has to be corrected where it comes from.
