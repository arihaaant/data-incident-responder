**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `unique_stg_orders_order_key` fail (300 rows): Got 300 results, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.orders`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`, `stg_orders`

**Evidence**

The unique_stg_orders_order_key test failed with 300 duplicate rows. raw.orders contains duplicate order_key values (e.g., order_key 2979 appears twice) but the duplicate rows are identical across all columns. This indicates a batch was delivered twice. Deduplicating in the staging model resolves the uniqueness violation without losing data.
