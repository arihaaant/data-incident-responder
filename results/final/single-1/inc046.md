**Status:** Escalated to the owner of model.fct_orders. Nothing was changed.

## What broke

- `assert_orders_fresh` fail (1 rows): Got 1 result, configured to fail if != 0

## Diagnosis

- **Started at:** `model.fct_orders`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`

**Evidence**

The assert_orders_fresh test fails with 1 row, indicating a freshness issue. The stg_orders model loads data from raw.orders without any transformation of the loaded_at column, which now contains static historic dates (e.g., 1998-07-31) instead of recent ingestion timestamps. This suggests the source raw.orders changed its loaded_at semantics. The fix is to patch the stg_orders model to set loaded_at to the current timestamp at load time, preserving original data while satisfying freshness expectations.
