## What broke

- `assert_daily_revenue_one_row_per_region` fail (3659 rows): Got 3659 results, configured to fail if != 0

## Diagnosis

- **Started at:** `model.fct_daily_revenue`
- **Cause:** a change in a model

**Evidence**

The test `assert_daily_revenue_one_row_per_region` failed with 3659 rows, meaning the model produced multiple rows per (order_date, region_name). The model's SQL grouped by order_date, region_name, priority but only selected order_date and region_name, causing duplicate rows for each priority. Removing priority from the GROUP BY resolves the issue; a trial patch succeeded with all tests passing.
