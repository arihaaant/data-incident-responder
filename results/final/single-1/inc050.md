The stg_orders model likely selects order_date directly, causing missing values or mismatched column names. However the check not_null_stg_orders_order_date passes, indicating the model may have aliased correctly. The real issue is the failing check (not provided) likely about order_date freshness. The raw.orders _loaded_at aligns with stg_orders loaded_at, but the order_date column exists in stg_orders with no nulls. The root cause appears to be a code change in stg_orders model that mis-mapped the column name, leading to downstream failures in fct_orders. Therefore patch stg_orders to correctly map o_orderdate to order_date.
