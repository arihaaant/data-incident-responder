# Incident inc039

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `unique_stg_parts_part_key` fail (200 rows): Got 200 results, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.part`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`, `stg_parts`

**Evidence**

The unique test on stg_parts.part_key failed with 200 duplicate rows. raw.part contains duplicate p_partkey values (e.g., p_partkey 116 appears twice) but all other columns are identical, indicating identical duplicate rows from a redelivered batch. Policy dictates deduplicating in the staging model. Adding DISTINCT removes the duplicates without data loss, fixing the unique constraint.
