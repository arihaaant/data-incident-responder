# Incident inc019

**Status:** Escalated to the owner of raw.lineitem. Nothing was changed.

## What broke

- `not_null_stg_lineitem_discount` fail (12002 rows): Got 12002 results, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.lineitem`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`, `stg_lineitem`

**Evidence**

The failing test not_null_stg_lineitem_discount expects zero nulls in the discount column of stg_lineitem. The upstream raw table raw.lineitem contains 12,002 null values in l_discount (total rows 60,175, non‑null 48,173). The staging model stg_lineitem simply selects l_discount without transformation, so the nulls are propagated downstream, causing the test failure. Since the issue originates in the source data and cannot be fixed by a downstream patch without inventing data, the incident should be escalated to the source owner.

**Column profile** `raw.lineitem.l_discount` (decimal(15,2) to decimal(15,2)): converts without loss
