## What broke

- `unique_stg_lineitem_order_line_id` fail (5639 rows): Got 5639 results, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.lineitem`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`, `stg_lineitem`

**Evidence**

The unique test on stg_lineitem.order_line_id failed with 5,639 duplicate rows. Raw lineitem contains exact duplicate rows (same orderkey and linenumber) as shown by grouping on l_orderkey, l_linenumber which returns counts >1. Since duplicates are identical across all columns, policy dictates deduplication in the staging model. Adding DISTINCT to the SELECT removes duplicate order_line_id rows, and try_patch confirms all tests now pass.
