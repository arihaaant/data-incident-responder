**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `unique_stg_orders_order_key` fail (3000 rows): Got 3000 results, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.orders`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`, `stg_orders`

**Evidence**

The unique_stg_orders_order_key test failed with 3000 duplicate rows. Raw.orders contains duplicate order_key rows where all columns are identical (e.g., order_key 195 appears twice with identical data). This indicates a batch was delivered twice. Deduplicating in the staging model using SELECT DISTINCT resolves the uniqueness violation without losing data, as duplicates are exact copies.
