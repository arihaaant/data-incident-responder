# Incident inc023

**Status:** Escalated to the owner of raw.lineitem. Nothing was changed.

## What broke

- `not_null_stg_lineitem_order_key` fail (1550 rows): Got 1550 results, configured to fail if != 0
- `not_null_stg_lineitem_order_line_id` fail (1550 rows): Got 1550 results, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.lineitem`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`, `stg_lineitem`

**Evidence**

The not_null checks on stg_lineitem (order_key and order_line_id) failed with 1550 rows. In raw.lineitem, 1550 rows have l_orderkey NULL, while l_linenumber is never null. stg_lineitem builds order_key directly from l_orderkey and order_line_id from l_orderkey||'-'||l_linenumber, so the nulls propagate. The source data is missing required order keys, so the problem originates upstream and must be escalated to the source owner.

```sql
SELECT COUNT(*) AS total_rows, COUNT(order_key) AS not_null_order_key, COUNT(order_line_id) AS not_null_order_line_id FROM raw.lineitem
```

```sql
SELECT COUNT(*) AS total_rows,
       SUM(CASE WHEN l_orderkey IS NULL THEN 1 ELSE 0 END) AS null_orderkey,
       SUM(CASE WHEN l_linenumber IS NULL THEN 1 ELSE 0 END) AS null_linenumber
FROM raw.lineitem
```

</details>

No change was made to the warehouse. The data has to be corrected where it comes from.
