# Incident inc032

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `unique_stg_orders_order_key` fail (1200 rows): Got 1200 results, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.orders`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`, `stg_orders`

**Evidence**

The unique_stg_orders_order_key test failed with 1200 duplicate rows. Raw.orders contains duplicate o_orderkey values where all other columns are identical (e.g., o_orderkey 1216 appears twice with identical data). This indicates the source delivered the same batch twice. According to policy, identical duplicate rows should be deduplicated in the staging model. Adding SELECT DISTINCT in stg_orders removes the duplicates, and try_patch confirms all tests now pass.
