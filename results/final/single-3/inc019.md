# Incident inc019

**Status:** Escalated to the owner of raw.lineitem. Nothing was changed.

## What broke

- `not_null_stg_lineitem_discount` fail (12002 rows): Got 12002 results, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.lineitem`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`, `stg_lineitem`

**Evidence**

The not_null_stg_lineitem_discount test failed with 12002 rows. Querying raw.lineitem shows 12002 rows where l_discount is NULL (out of 60175 total). The staging model stg_lineitem simply selects l_discount from the source without any transformation, so the nulls are present in the source data. This is an upstream data issue; the source owner must address the missing discount values.

```sql
SELECT COUNT(*) AS cnt, COUNT(DISTINCT discount) AS distinct_discount FROM raw.lineitem
```
```sql
SELECT COUNT(*) AS total, COUNT(*) FILTER (WHERE l_discount IS NULL) AS nulls FROM raw.lineitem
```

</details>

## What was done

No change was made to the warehouse. The data has to be corrected where it comes from.
