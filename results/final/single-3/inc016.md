**Status:** Escalated to the owner of raw.customer. Nothing was changed.

## What broke

- `not_null_stg_customers_market_segment` fail (375 rows): Got 375 results, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.customer`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `dim_customers`, `fct_daily_revenue`, `fct_orders`, `stg_customers`

**Evidence**

The not_null test on stg_customers.market_segment failed with 375 rows. In raw.customer, column c_mktsegment has 375 null values out of 1500 rows (SELECT COUNT(*) ...). The staging model simply passes through this column, so the nulls originate from the source data.

```sql
SELECT COUNT(*) AS total_rows, SUM(CASE WHEN c_mktsegment IS NULL THEN 1 ELSE 0 END) AS null_mktsegment FROM raw.customer
```

</details>

No change was made to the warehouse. The data has to be corrected where it comes from.
