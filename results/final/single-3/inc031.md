# Incident inc031

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `unique_stg_orders_order_key` fail (300 rows): Got 300 results, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.orders`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`, `stg_orders`

**Evidence**

The unique_stg_orders_order_key test failed with 300 duplicate order_key rows. Raw.orders contains duplicate rows for the same order_key (e.g., order_key 8800 appears twice with identical column values). The staging model stg_orders selects directly from raw.orders, propagating duplicates. Since the duplicate rows are identical in every column, policy dictates deduplication in the staging model. Applying SELECT DISTINCT removes the duplicates, and try_patch confirms all tests now pass.
