## Diagnosis

- **Started at:** `model.dim_customers`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`

**Evidence**

All upstream tables have matching row counts and no missing joins. dim_customers joins stg_customers (1500 rows) with stg_nations (25) and stg_regions (5) resulting in 1319 rows, indicating some customers dropped due to join mismatches. The join to stg_nations is fine (no missing nations). Likely the join to stg_regions drops customers where region_key mismatches or region_name values not in accepted list. The code uses join on n.region_key = r.region_key, but stg_regions may have fewer rows than expected, causing loss. This is a code issue in dim_customers model.
