# Incident inc053

**Status:** Escalated to the owner of raw.orders. Nothing was changed.

## What broke

- `assert_orders_fresh` fail (1 rows): Got 1 result, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.orders`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`, `stg_orders`

**Evidence**

The failing test assert_orders_fresh expects order_date to be equal to loaded_at (or not later). In staging.stg_orders, every row has loaded_at exactly one day after order_date (diff=1), as shown by queries on datediff. The stg_orders model simply selects columns from source('raw','orders') without transformation, so the discrepancy originates in the raw source table's _loaded_at values being offset by one day. Since the data issue is in the source, it must be escalated to the source owner.
