# Incident inc034

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `unique_stg_lineitem_order_line_id` fail (1550 rows): Got 1550 results, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.lineitem`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`, `stg_lineitem`

**Evidence**

The unique test on stg_lineitem.order_line_id failed with 1550 duplicate rows. Raw.lineitem has 61,725 rows but only 60,175 distinct order_line_id values (SELECT COUNT(*) vs COUNT(DISTINCT l_orderkey || '-' || l_linenumber)). The duplicates are exact copies across all columns (e.g., orderkey 1378, linenumber 4 appears twice with identical values). According to policy, identical duplicate rows are a delivery issue and should be deduplicated in the staging model. Adding DISTINCT to the select removes the duplicates and all tests pass (try_patch succeeded).
