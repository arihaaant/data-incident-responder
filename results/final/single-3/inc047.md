# Incident inc047

**Status:** Escalated to the owner of raw.orders. Nothing was changed.

## What broke

- `assert_orders_fresh` fail (1 rows): Got 1 result, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.orders`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`, `stg_orders`

**Evidence**

The freshness check asserts order_date equals CAST(loaded_at AS DATE), but for every row in staging.stg_orders the loaded_at timestamp is exactly one day later than order_date (e.g., order_key 1: order_date 1996-01-02, loaded_at 1996-01-03). The raw source table raw.orders shows the same pattern in its _loaded_at column, indicating the source data provides a load timestamp that is offset by one day. This discrepancy originates in the source raw.orders data, not in the dbt model logic.
