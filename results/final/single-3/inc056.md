- `assert_orders_fresh` fail (1 rows): Got 1 result, configured to fail if != 0
- `relationships_stg_lineitem_order_key__order_key__ref_stg_orders_` fail (1225 rows): Got 1225 results, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.orders`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`, `stg_orders`

**Evidence**

Raw table raw.orders has 319 rows where _loaded_at >= date '1998-06-15' (SELECT COUNT(*) FROM raw.orders WHERE _loaded_at >= date '1998-06-15' returned 319). The staging model stg_orders filters out these rows (WHERE _loaded_at < date '1998-06-15'), resulting in a reduced row count (14681) versus the expected full set. The presence of these late-loaded rows in the source is the upstream data issue causing downstream checks to fail.
