# Incident inc061

**Status:** Escalated to the owner of raw.lineitem. Nothing was changed.

## What broke

- `model.tpch_warehouse.stg_lineitem` error: Compilation Error in model stg_lineitem (models/staging/stg_lineitem.sql)

## Diagnosis

- **Started at:** `source.raw.lineitem`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`, `stg_lineitem`

**Evidence**

The staging model stg_lineitem fails contract checks: column extended_price is defined as DECIMAL(15,2) but the source raw.lineitem.l_extendedprice is BIGINT, and net_revenue is defined as DECIMAL(18,4) but the expression yields DECIMAL(35,2). Profile of raw.lineitem.l_extendedprice shows lossless = false because the source no longer provides fractional digits expected by the contract, indicating a type/format change that is not losslessly convertible. According to team policy, we can only patch a type change if the profile reports lossless, otherwise we must escalate. Therefore the problem originates from the raw.lineitem source table.

**Column profile** `raw.lineitem.l_extendedprice` (bigint to decimal(15,2)): would lose data: no value has a fractional part although the contract keeps 2 decimal places; if the source used to send fractions, they were dropped before arriving
