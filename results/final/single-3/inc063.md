# Incident inc063

**Status:** Escalated to the owner of raw.customer. Nothing was changed.

## What broke

- `model.tpch_warehouse.stg_customers` error: Compilation Error in model stg_customers (models/staging/stg_customers.sql)

## Diagnosis

- **Started at:** `source.raw.customer`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `dim_customers`, `fct_daily_revenue`, `fct_orders`, `stg_customers`

**Evidence**

The stg_customers model failed contract validation because its column account_balance is defined as VARCHAR, while the staging contract expects DECIMAL(15,2). The raw source column c_acctbal is VARCHAR. Profiling shows conversion to DECIMAL(15,2) is not lossless: raw values have at most 1 decimal place, so converting to 2 decimal places would add missing digits that cannot be recovered. According to team policy, type changes can only be patched if lossless; here they are not, so the issue must be escalated to the source owner. The problem originates at raw.customer.

**Column profile** `raw.customer.c_acctbal` (varchar to decimal(15,2)): would lose data: values arrive with at most 1 decimal places where the contract keeps 2; the missing digits can't be recovered

## What was done

No change was made to the warehouse. The data has to be corrected where it comes from.
