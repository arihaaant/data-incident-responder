# Incident inc038

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `unique_stg_customers_customer_key` fail (225 rows): Got 225 results, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.customer`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `dim_customers`, `fct_daily_revenue`, `fct_orders`, `stg_customers`

**Evidence**

The unique_stg_customers_customer_key test failed (225 duplicate keys). Raw.customer contains duplicate rows for many c_custkey values. A query showed that for every duplicated key the rows are identical across all columns (total rows = 2, distinct rows = 1). According to policy, identical duplicate batches should be deduplicated in the staging model. Adding SELECT DISTINCT in stg_customers removes the duplicate rows, and try_patch confirms all tests now pass.
