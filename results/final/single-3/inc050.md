# Incident inc050

**Status:** Escalated to the owner of raw.orders. Nothing was changed.

## What broke

- `assert_orders_fresh` fail (1 rows): Got 1 result, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.orders`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`, `stg_orders`

**Evidence**

Raw table raw.orders shows _loaded_at is exactly one day after o_orderdate for all rows (e.g., orderkey 1: o_orderdate 1996-01-02, _loaded_at 1996-01-03). The staging model stg_orders simply maps these columns, preserving the one‑day offset. No rows violate order_date > loaded_at, but the business rule expects loaded_at not to be later than order_date (or within the same day). The issue originates in the source data, not in any dbt model.
