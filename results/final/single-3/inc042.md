**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `unique_dim_customers_customer_key` fail (1500 rows): Got 1500 results, configured to fail if != 0

## Diagnosis

- **Started at:** `model.dim_customers`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`

**Evidence**

The `unique_dim_customers_customer_key` test failed with 1500 duplicate rows. `stg_customers` has 1500 distinct `customer_key` values, but `dim_customers` contains 7500 rows, indicating each customer was duplicated 5 times. Inspecting `dim_customers` SQL shows an incorrect join: `join {{ ref('stg_regions') }} r on n.region_key = n.region_key`, which is always true and creates a Cartesian product with all regions (5 rows). Changing the join condition to `n.region_key = r.region_key` restores the proper 1‑to‑1 relationship, eliminating duplicate rows and satisfying the uniqueness test.
