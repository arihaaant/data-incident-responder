**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `unique_stg_customers_customer_key` fail (75 rows): Got 75 results, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.customer`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `dim_customers`, `fct_daily_revenue`, `fct_orders`, `stg_customers`

**Evidence**

The unique_stg_customers_customer_key test failed with 75 duplicate rows. raw.customer has 1,575 rows but only 1,500 distinct c_custkey values, indicating duplicate deliveries. For each duplicate key (e.g., c_custkey = 237) all column values are identical, confirming exact duplicate rows. Policy dictates deduplicating identical rows in the staging model. Adding DISTINCT on c_custkey (and other columns) removes the duplicates, and try_patch shows all tests now pass.
