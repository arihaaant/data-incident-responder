# Incident inc021

**Status:** Escalated to the owner of raw.customer. Nothing was changed.

## What broke

- `not_null_stg_customers_nation_key` fail (120 rows): Got 120 results, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.customer`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `dim_customers`, `fct_daily_revenue`, `fct_orders`, `stg_customers`

**Evidence**

raw.customer has 1500 rows, 120 rows with NULL c_nationkey (SELECT COUNT(*)=1500, COUNT(c_nationkey)=1380, null_rows=120). stg_customers maps c_nationkey directly to nation_key, so nulls propagate, causing not_null test failure. Issue originates in source data.

<details><summary>2 queries run during the investigation</summary>

```sql
SELECT COUNT(*) AS total_rows, COUNT(nation_key) AS not_null_rows FROM raw.customer
```
```sql
SELECT COUNT(*) AS total_rows, COUNT(c_nationkey) AS not_null_rows, SUM(CASE WHEN c_nationkey IS NULL THEN 1 ELSE 0 END) AS null_rows FROM raw.customer
```

</details>

## What was done

No change was made to the warehouse. The data has to be corrected where it comes from.
