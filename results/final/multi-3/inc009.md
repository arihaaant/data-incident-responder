# Incident inc009

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `model.tpch_warehouse.stg_lineitem` error: Runtime Error in model stg_lineitem (models/staging/stg_lineitem.sql)

## Diagnosis

- **Started at:** `source.raw.lineitem`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`, `stg_lineitem`

**Evidence**

stg_lineitem model compilation error: references column l_shipdate which is missing in raw.lineitem. Raw table now has l_ship_date (underscore). This is the first point where the problem appears; upstream raw schema changed (column rename). Policy: rename handled by updating staging model, so patch.

## What was done

Proposed a change to `models/staging/stg_lineitem.sql`. The upstream raw.lineitem table renamed the ship date column from `l_shipdate` to `l_ship_date`. The staging model `stg_lineitem` still referenced the old name, causing a compilation error. Updated the SELECT list to use `l_ship_date` while preserving the original alias `ship_date` and leaving all other columns unchanged.

```diff
--- a/models/staging/stg_lineitem.sql
+++ b/models/staging/stg_lineitem.sql
@@ -9,6 +9,6 @@
     l_discount as discount,
     l_tax as tax,
     l_returnflag as return_flag,
-    l_shipdate as ship_date,
+    l_ship_date as ship_date,
     l_extendedprice * (1 - l_discount) as net_revenue
 from {{ source('raw', 'lineitem') }}
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix updates staging model to reference renamed column l_ship_date, correctly handling upstream schema change.
