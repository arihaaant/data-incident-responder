# Incident inc015

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `model.tpch_warehouse.stg_nations` error: Runtime Error in model stg_nations (models/staging/stg_nations.sql)

## Diagnosis

- **Started at:** `source.raw.nation`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `dim_customers`, `fct_daily_revenue`, `fct_orders`, `stg_nations`

**Evidence**

raw.nation schema shows column n_region_key, not n_regionkey. stg_nations model references n_regionkey causing binder error. Renamed column is upstream change; staging model should be patched to use n_region_key.

## What was done

Proposed a change to `models/staging/stg_nations.sql`. The upstream raw.nation source renamed the column from n_regionkey to n_region_key. The staging model referenced the old name, causing a binder error. Updated the SELECT to use n_region_key while preserving column aliases and types. No other changes were made.

```diff
--- a/models/staging/stg_nations.sql
+++ b/models/staging/stg_nations.sql
@@ -1,5 +1,5 @@
 select
     n_nationkey as nation_key,
     n_name as nation_name,
-    n_regionkey as region_key
+    n_region_key as region_key
 from {{ source('raw', 'nation') }}
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix correctly updates the staging model to reference the renamed column n_region_key, addressing the upstream schema change without masking data.
