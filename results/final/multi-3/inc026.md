# Incident inc026

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `not_null_stg_lineitem_extended_price` fail (29778 rows): Got 29778 results, configured to fail if != 0

## Diagnosis

- **Started at:** `model.stg_lineitem`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`

**Evidence**

raw.lineitem has 60,175 rows, 0 null l_extendedprice. 29,778 rows have l_returnflag <> 'N'. stg_lineitem model sets extended_price = CASE WHEN l_returnflag = 'N' THEN l_extendedprice END, producing NULL for those rows. The not_null test on stg_lineitem_extended_price fails with exactly 29,778 nulls, matching the count of non‑'N' rows. Therefore the nulls are introduced by the model's conditional logic, not upstream data.

<details><summary>2 queries run during the investigation</summary>

```sql
SELECT COUNT(*) AS total_rows, COUNT(*) FILTER (WHERE extendedprice IS NULL) AS null_extendedprice FROM raw.lineitem
```
```sql
SELECT COUNT(*) AS total_rows,
       COUNT(*) FILTER (WHERE l_extendedprice IS NULL) AS null_extendedprice,
       COUNT(*) FILTER (WHERE l_returnflag <> 'N') AS non_N_returnflag
FROM raw.lineitem
```

</details>

## What was done

Proposed a change to `models/staging/stg_lineitem.sql`. The original model set `extended_price` using a CASE that returned NULL for any rows where `l_returnflag` <> 'N'. This caused 29,778 null values, failing the `not_null` test on `stg_lineitem_extended_price`. The test expects every row to have a non‑null `extended_price`, and the source data already guarantees `l_extendedprice` is never null. By assigning `l_extendedprice` directly to `extended_price`, we preserve the original data type (e.g., decimal(15,2)) and eliminate the introduced nulls, allowing the not_null test to pass while keeping all other columns unchanged.

```diff
--- a/models/staging/stg_lineitem.sql
+++ b/models/staging/stg_lineitem.sql
@@ -5,7 +5,7 @@
     l_partkey as part_key,
     l_suppkey as supplier_key,
     l_quantity as quantity,
-    case when l_returnflag = 'N' then l_extendedprice end as extended_price,
+    l_extendedprice as extended_price,
     l_discount as discount,
     l_tax as tax,
     l_returnflag as return_flag,
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix removes erroneous CASE that introduced nulls, directly maps l_extendedprice preserving data integrity. No type/format change, and the change addresses the root cause.
