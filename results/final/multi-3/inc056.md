## Diagnosis

- **Started at:** `model.stg_orders`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`

**Evidence**

stg_orders model filters out rows with _loaded_at >= '1998-06-15' (319 rows). Freshness test fails (1 stale row) and foreign key relationship shows 1225 orphan lineitem rows because recent orders are missing. Raw.orders has correct distinct order keys (15000) matching lineitem, and raw data shows no missing columns. The issue originates from the WHERE clause in stg_orders, a code change, not upstream data.

## What was done

Proposed a change to `models/staging/stg_orders.sql`. Removed the erroneous WHERE clause that filtered out rows with _loaded_at >= '1998-06-15'. This restores all order records, fixing freshness and relationship checks while preserving column names and types.

```diff
--- a/models/staging/stg_orders.sql
+++ b/models/staging/stg_orders.sql
@@ -7,4 +7,3 @@
     o_orderpriority as priority,
     _loaded_at as loaded_at
 from {{ source('raw', 'orders') }}
-where _loaded_at < date '1998-06-15'
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix removes erroneous WHERE filter that dropped recent rows, directly addressing the root cause without masking data or altering column semantics.
