# Incident inc006

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `model.tpch_warehouse.stg_customers` error: Runtime Error in model stg_customers (models/staging/stg_customers.sql)

## Diagnosis

- **Started at:** `source.raw.customer`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `dim_customers`, `fct_daily_revenue`, `fct_orders`, `stg_customers`

**Evidence**

The raw.customer table has column c_nation_key, not c_nationkey. The stg_customers model selects c_nationkey, causing a binder error. This is a schema rename upstream; fixing by updating the model to use c_nation_key patches the issue.

## What was done

Proposed a change to `models/staging/stg_customers.sql`. The upstream raw.customer table renamed the column from c_nationkey to c_nation_key. The stg_customers model referenced the old name, causing a binder error. Updated the SELECT to use c_nation_key while preserving all other column mappings and types.

```diff
--- a/models/staging/stg_customers.sql
+++ b/models/staging/stg_customers.sql
@@ -3,7 +3,7 @@
     c_name as customer_name,
     c_address as address,
     c_phone as phone,
-    c_nationkey as nation_key,
+    c_nation_key as nation_key,
     c_mktsegment as market_segment,
     c_acctbal as account_balance
 from {{ source('raw', 'customer') }}
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix correctly updates the model to use the renamed column c_nation_key, addressing the binder error. No type/format conversion involved, so lack of column profile is acceptable.
