# Incident inc033

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `unique_stg_orders_order_key` fail (3000 rows): Got 3000 results, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.orders`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`, `stg_orders`

**Evidence**

raw.orders has 18000 rows but only 15000 distinct order_key, indicating 3000 duplicate rows. Duplicate rows are exact copies (distinct rows per order_key =1). Therefore duplicates stem from source ingestion; policy says identical duplicates are batch delivered twice, fix by deduplicating in stg_orders.

## What was done

Proposed a change to `models/staging/stg_orders.sql`. Added a CTE to read from the raw orders source, then applied row_number partitioned by order_key to drop exact duplicate rows. Since duplicates are identical, keeping the first (earliest loaded_at) satisfies the unique constraint without altering column names or types.

```diff
--- a/models/staging/stg_orders.sql
+++ b/models/staging/stg_orders.sql
@@ -1,9 +1,34 @@
+with source_data as (
+    select
+        o_orderkey as order_key,
+        o_custkey as customer_key,
+        o_orderstatus as order_status,
+        o_totalprice as total_price,
+        o_orderdate as order_date,
+        o_orderpriority as priority,
+        _loaded_at as loaded_at
+    from {{ source('raw', 'orders') }}
+),
+-- Keep only the first occurrence of each order_key. Duplicates are exact copies, so any row is fine.
+deduped as (
+    select
+        order_key,
+        customer_key,
+        order_status,
+        total_price,
+        order_date,
+        priority,
+        loaded_at,
+        row_number() over (partition by order_key order by loaded_at) as rn
+    from source_data
+)
 select
-    o_orderkey as order_key,
-    o_custkey as customer_key,
-    o_orderstatus as order_status,
-    o_totalprice as total_price,
-    o_orderdate as order_date,
-    o_orderpriority as priority,
-    _loaded_at as loaded_at
-from {{ source('raw', 'orders') }}
+    order_key,
+    customer_key,
+    order_status,
+    total_price,
+    order_date,
+    priority,
+    loaded_at
+from deduped
+where rn = 1
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix correctly deduplicates exact duplicate rows by order_key, preserving data integrity without masking or altering columns. Addresses root cause as required.
