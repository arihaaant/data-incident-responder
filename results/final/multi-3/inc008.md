# Incident inc008

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `model.tpch_warehouse.stg_lineitem` error: Runtime Error in model stg_lineitem (models/staging/stg_lineitem.sql)

## Diagnosis

- **Started at:** `source.raw.lineitem`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`, `stg_lineitem`

**Evidence**

stg_lineitem model references l_extendedprice which is not present in raw.lineitem. raw.lineitem schema shows column l_extended_price (underscore). This rename is a lossless schema change; the fix is to patch the staging model to use the new column name.

## What was done

Proposed a change to `models/staging/stg_lineitem.sql`. The source raw.lineitem renamed the column from l_extendedprice to l_extended_price. Updated the staging model to reference the correct column name in both the extended_price alias and the net_revenue calculation, preserving all other columns and logic.

```diff
--- a/models/staging/stg_lineitem.sql
+++ b/models/staging/stg_lineitem.sql
@@ -5,10 +5,10 @@
     l_partkey as part_key,
     l_suppkey as supplier_key,
     l_quantity as quantity,
-    l_extendedprice as extended_price,
+    l_extended_price as extended_price,
     l_discount as discount,
     l_tax as tax,
     l_returnflag as return_flag,
     l_shipdate as ship_date,
-    l_extendedprice * (1 - l_discount) as net_revenue
+    l_extended_price * (1 - l_discount) as net_revenue
 from {{ source('raw', 'lineitem') }}
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix correctly updates staging model to use renamed column l_extended_price, preserving logic and addressing upstream schema change.
