# Incident inc041

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `unique_stg_orders_order_key` fail (363 rows): Got 363 results, configured to fail if != 0

## Diagnosis

- **Started at:** `model.stg_orders`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`

**Evidence**

raw.orders has 15000 rows and 15000 distinct o_orderkey (unique). stg_orders model selects from raw.orders and unions all the same rows plus a filtered subset where o_orderstatus='P', duplicating those rows. This creates 363 duplicate order_key values, causing the unique_stg_orders_order_key check to fail.

<details><summary>2 queries run during the investigation</summary>

```sql
SELECT COUNT(*) AS total_rows, COUNT(DISTINCT order_key) AS distinct_keys FROM raw.orders
```
```sql
SELECT COUNT(*) AS total_rows, COUNT(DISTINCT o_orderkey) AS distinct_keys FROM raw.orders
```

</details>

## What was done

Proposed a change to `models/staging/stg_orders.sql`. Removed the erroneous UNION ALL that re‑added rows where `o_orderstatus = 'P'`. The original model duplicated those rows, causing 363 duplicate `order_key` values and failing the `unique_stg_orders_order_key` check. By selecting directly from the source without the extra union, we preserve the intended row set and maintain all column names and types.

```diff
--- a/models/staging/stg_orders.sql
+++ b/models/staging/stg_orders.sql
@@ -7,7 +7,3 @@
     o_orderpriority as priority,
     _loaded_at as loaded_at
 from {{ source('raw', 'orders') }}
-union all
-select o_orderkey, o_custkey, o_orderstatus, o_totalprice, o_orderdate, o_orderpriority, _loaded_at
-from {{ source('raw', 'orders') }}
-where o_orderstatus = 'P'
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix removes erroneous UNION ALL that duplicated rows, directly addressing duplicate order_key issue without masking data or altering column semantics.
