# Incident inc004

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `model.tpch_warehouse.stg_customers` error: Runtime Error in model stg_customers (models/staging/stg_customers.sql)

## Diagnosis

- **Started at:** `source.raw.customer`, column `c_market_segment`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `dim_customers`, `fct_daily_revenue`, `fct_orders`, `stg_customers`

**Evidence**

The raw.customer table now has column c_market_segment instead of c_mktsegment. The staging model stg_customers references c_mktsegment, causing a binder error. Renamed column policy says update staging model to use new name. Root cause is schema change in source raw.customer.

## What was done

Proposed a change to `models/staging/stg_customers.sql`. The source table raw.customer renamed column c_mktsegment to c_market_segment. The staging model referenced the old name, causing a binder error. Updated the SELECT to use c_market_segment while preserving all other column mappings and types.

```diff
--- a/models/staging/stg_customers.sql
+++ b/models/staging/stg_customers.sql
@@ -4,6 +4,6 @@
     c_address as address,
     c_phone as phone,
     c_nationkey as nation_key,
-    c_mktsegment as market_segment,
+    c_market_segment as market_segment,
     c_acctbal as account_balance
 from {{ source('raw', 'customer') }}
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix correctly updates staging model to reference renamed column c_market_segment, addressing the binder error caused by schema change. No type/format conversion needed, so lack of column profile is acceptable.
