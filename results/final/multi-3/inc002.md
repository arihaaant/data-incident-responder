# Incident inc002

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `model.tpch_warehouse.stg_orders` error: Runtime Error in model stg_orders (models/staging/stg_orders.sql)

## Diagnosis

- **Started at:** `source.raw.orders`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`, `stg_orders`

**Evidence**

The raw.orders table schema lists column o_customer_key and does not contain o_custkey. The failing model stg_orders references o_custkey, causing a binder error. This indicates a source column rename, so the issue originates at the source; fixing requires updating the staging model to map o_customer_key to customer_key.

## What was done

Proposed a change to `models/staging/stg_orders.sql`. The source table raw.orders renamed the column from o_custkey to o_customer_key. The staging model referenced the old name, causing a binder error. Updated the SELECT to use o_customer_key while preserving all other column mappings and types.

```diff
--- a/models/staging/stg_orders.sql
+++ b/models/staging/stg_orders.sql
@@ -1,6 +1,6 @@
 select
     o_orderkey as order_key,
-    o_custkey as customer_key,
+    o_customer_key as customer_key,
     o_orderstatus as order_status,
     o_totalprice as total_price,
     o_orderdate as order_date,
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix correctly updates staging model to use renamed source column o_customer_key, preserving all other mappings. No type/format conversion needed, so missing profile is acceptable.
