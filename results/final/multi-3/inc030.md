# Incident inc030

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `not_null_stg_lineitem_discount` fail (5419 rows): Got 5419 results, configured to fail if != 0

## Diagnosis

- **Started at:** `model.stg_lineitem`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`

**Evidence**

raw.lineitem has 0 nulls but 5,419 rows where l_discount = 0. stg_lineitem model uses case when l_discount > 0 then l_discount end, turning zeros into NULLs, causing not_null test failure. The issue is in the model's SQL, not source data.

<details><summary>2 queries run during the investigation</summary>

```sql
SELECT COUNT(*) AS total_rows, COUNT(discount) AS not_null_discount, SUM(CASE WHEN discount IS NULL THEN 1 ELSE 0 END) AS null_discount FROM raw.lineitem
```
```sql
SELECT COUNT(*) AS total, SUM(CASE WHEN l_discount IS NULL THEN 1 ELSE 0 END) AS nulls, SUM(CASE WHEN l_discount = 0 THEN 1 ELSE 0 END) AS zeros FROM raw.lineitem
```

</details>

## What was done

Proposed a change to `models/staging/stg_lineitem.sql`. The not_null test on `discount` was failing because the model converted zero discounts to NULL using `case when l_discount > 0 then l_discount end`. Since the source data contains valid zero values, they should be retained. Replaced the CASE expression with a direct column reference `l_discount as discount`, preserving zeros and satisfying the not_null constraint while leaving all other logic unchanged.

```diff
--- a/models/staging/stg_lineitem.sql
+++ b/models/staging/stg_lineitem.sql
@@ -6,7 +6,8 @@
     l_suppkey as supplier_key,
     l_quantity as quantity,
     l_extendedprice as extended_price,
-    case when l_discount > 0 then l_discount end as discount,
+    -- Preserve discount values including zeros; previously zeros were turned into NULLs
+    l_discount as discount,
     l_tax as tax,
     l_returnflag as return_flag,
     l_shipdate as ship_date,
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix directly addresses root cause by preserving zero discount values instead of converting them to NULL, restoring not_null constraint without masking data or altering other logic.
