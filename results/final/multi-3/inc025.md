# Incident inc025

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `not_null_fct_orders_region_name` fail (14744 rows): Got 14744 results, configured to fail if != 0

## Diagnosis

- **Started at:** `model.dim_customers`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`

**Evidence**

fct_orders.region_name nulls (14744) stem from left join to dim_customers where c.customer_key is null for 14744 orders. Join test shows only 256 of 15000 stg_orders rows find a matching dim_customers row. dim_customers has only 24 rows and no null region_name, indicating many customers were dropped upstream. Likely dim_customers model uses inner joins between stg_customers, stg_nations, stg_regions, discarding customers without matching nation/region. This is a code issue in the dim_customers model; raw source tables have full data.

## What was done

Proposed a change to `models/marts/dim_customers.sql`. The original model incorrectly joined stg_customers to stg_nations using the customer_key, which caused most customers to be dropped because the keys don't match. It also used an inner join to stg_regions, further discarding rows without a matching region. The fix changes the join to use the proper foreign key relationships: `c.nation_key = n.nation_key` and makes the join to regions a left join (`n.region_key = r.region_key`). This preserves all customers, ensuring downstream models like fct_orders receive non‑null region_name values where appropriate, and resolves the failing not_null check.

```diff
--- a/models/marts/dim_customers.sql
+++ b/models/marts/dim_customers.sql
@@ -6,5 +6,5 @@
     n.nation_name,
     r.region_name
 from {{ ref('stg_customers') }} c
-left join {{ ref('stg_nations') }} n on c.customer_key = n.nation_key
-join {{ ref('stg_regions') }} r on n.region_key = r.region_key
+left join {{ ref('stg_nations') }} n on c.nation_key = n.nation_key
+left join {{ ref('stg_regions') }} r on n.region_key = r.region_key
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix corrects wrong join key and changes inner join to left join, restoring dropped customers and eliminating null region_name in downstream fact. Addresses root cause without masking data.
