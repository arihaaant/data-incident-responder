# Incident inc043

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `unique_stg_customers_customer_key` fail (337 rows): Got 337 results, configured to fail if != 0

## Diagnosis

- **Started at:** `model.stg_customers`
- **Cause:** a change in a model
- **Downstream models affected:** `dim_customers`, `fct_daily_revenue`, `fct_orders`

**Evidence**

raw.customer has 1500 rows, distinct keys 1500. stg_customers has 1837 rows, distinct keys 1500, indicating 337 extra rows. Model SQL unions raw.customer with itself (union all) plus a filtered duplicate, creating duplicate customer_key rows. The uniqueness check fails due to this code error.

## What was done

Proposed a change to `models/staging/stg_customers.sql`. Removed the erroneous UNION ALL that duplicated rows. The original model selected all customers and then UNION ALL the same source filtered to `c_mktsegment = 'BUILDING'`, which re‑added those rows, causing 337 duplicate `customer_key` values and failing the uniqueness check. By keeping only the single SELECT (which already includes all rows), we preserve the required columns and types while ensuring each `customer_key` appears only once.

```diff
--- a/models/staging/stg_customers.sql
+++ b/models/staging/stg_customers.sql
@@ -7,7 +7,3 @@
     c_mktsegment as market_segment,
     c_acctbal as account_balance
 from {{ source('raw', 'customer') }}
-union all
-select c_custkey, c_name, c_address, c_phone, c_nationkey, c_mktsegment, c_acctbal
-from {{ source('raw', 'customer') }}
-where c_mktsegment = 'BUILDING'
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix removes erroneous UNION ALL that duplicated rows, restoring one-to-one mapping of customer_key and satisfying uniqueness check. No type/format changes involved.
