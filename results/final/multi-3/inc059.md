- `assert_orders_fresh` fail (1 rows): Got 1 result, configured to fail if != 0
- `relationships_stg_lineitem_order_key__order_key__ref_stg_orders_` fail (769 rows): Got 769 results, configured to fail if != 0

## Diagnosis

- **Started at:** `model.stg_orders`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`

**Evidence**

stg_orders filters out orders newer than 30 days (where o_orderdate < date '{{ var("as_of") }}' - interval 30 day'), resulting in 200 missing orders (raw count 15000 vs stg count 14800) and 769 lineitem rows with missing order_key references; assert_orders_fresh also fails. The filter is the source of the problem.

## What was done

Proposed a change to `models/staging/stg_orders.sql`. Removed the 30‑day freshness filter that was incorrectly dropping recent orders. The model now selects all rows from the raw orders source, preserving column names and types, which resolves the missing order rows and the downstream relationship failures.

```diff
--- a/models/staging/stg_orders.sql
+++ b/models/staging/stg_orders.sql
@@ -7,4 +7,3 @@
     o_orderpriority as priority,
     _loaded_at as loaded_at
 from {{ source('raw', 'orders') }}
-where o_orderdate < date '{{ var("as_of") }}' - interval 30 day
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix removes the erroneous 30‑day filter that caused missing recent orders and broken foreign key relationships. No data masking or type changes involved.
