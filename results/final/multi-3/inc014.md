# Incident inc014

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `model.tpch_warehouse.stg_parts` error: Runtime Error in model stg_parts (models/staging/stg_parts.sql)

## Diagnosis

- **Started at:** `source.raw.part`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`, `stg_parts`

**Evidence**

raw.part columns: p_partkey, p_name, p_mfgr, p_brand_name, p_type, p_size, p_container, p_retailprice, p_comment. stg_parts model selects p_brand which no longer exists, causing binder error. The source schema changed (p_brand renamed to p_brand_name). The fix is to patch the staging model to use p_brand_name.

## What was done

Proposed a change to `models/staging/stg_parts.sql`. The source schema changed: column `p_brand` was renamed to `p_brand_name`. The staging model `stg_parts` still referenced the old name, causing a binder error. Updated the SELECT to use `p_brand_name` while preserving the original output column name `brand` and keeping all other column mappings unchanged.

```diff
--- a/models/staging/stg_parts.sql
+++ b/models/staging/stg_parts.sql
@@ -1,7 +1,7 @@
 select
     p_partkey as part_key,
     p_name as part_name,
-    p_brand as brand,
+    p_brand_name as brand,
     p_type as part_type,
     p_retailprice as retail_price
 from {{ source('raw', 'part') }}
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix correctly updates staging model to reference renamed source column p_brand_name, preserving output column name. No data masking or type conversion involved.
