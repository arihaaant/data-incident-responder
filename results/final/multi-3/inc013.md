# Incident inc013

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `model.tpch_warehouse.stg_customers` error: Compilation Error in model stg_customers (models/staging/stg_customers.sql)

## Diagnosis

- **Started at:** `model.stg_customers`
- **Cause:** a change in a model
- **Downstream models affected:** `dim_customers`, `fct_daily_revenue`, `fct_orders`

**Evidence**

stg_customers model selects c_acctbal (VARCHAR) as account_balance, but contract expects DECIMAL(15,2). profile_column shows c_acctbal can be losslessly cast to DECIMAL(15,2). Adding CAST(c_acctbal AS DECIMAL(15,2)) fixes the type mismatch.

**Column profile** `raw.customer.c_acctbal` (varchar to decimal(15,2)): converts without loss

## What was done

Proposed a change to `models/staging/stg_customers.sql`. The contract for stg_customers expects the column `account_balance` to be DECIMAL(15,2) but the source column `c_acctbal` is VARCHAR. The column profile shows all values can be losslessly cast to DECIMAL(15,2). Updated the model to cast `c_acctbal` to the required type while preserving the original column name and order, fixing the contract mismatch.

```diff
--- a/models/staging/stg_customers.sql
+++ b/models/staging/stg_customers.sql
@@ -5,5 +5,5 @@
     c_phone as phone,
     c_nationkey as nation_key,
     c_mktsegment as market_segment,
-    c_acctbal as account_balance
+    cast(c_acctbal as decimal(15,2)) as account_balance
 from {{ source('raw', 'customer') }}
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix correctly casts source VARCHAR to required DECIMAL(15,2) as confirmed lossless by profile; addresses root cause without masking data.
