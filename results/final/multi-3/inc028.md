# Incident inc028

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `not_null_fct_orders_region_name` fail (14625 rows): Got 14625 results, configured to fail if != 0

## Diagnosis

- **Started at:** `model.fct_orders`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`

**Evidence**

Not_null test on fct_orders.region_name failed: 14,625 nulls out of 15,000 rows. fct_orders SQL uses `left join dim_customers c on o.order_key = c.customer_key`, which mismatches keys (order_key vs customer_key). Join result shows only 375 matches, leaving region_name null for the rest. Upstream tables raw.orders, stg_orders, dim_customers have correct data and no null region_name. The problem originates in the fct_orders model code; fixing the join to `on o.customer_key = c.customer_key` will resolve.

## What was done

Proposed a change to `models/marts/fct_orders.sql`. The original model joined `stg_orders` to `dim_customers` using `o.order_key = c.customer_key`, which mismatched keys and caused `region_name` to be null for most rows, failing the not_null test. Updated the join to correctly use `o.customer_key = c.customer_key`. All other columns, types, and logic remain unchanged.

```diff
--- a/models/marts/fct_orders.sql
+++ b/models/marts/fct_orders.sql
@@ -20,5 +20,6 @@
     coalesce(i.net_revenue, 0) as net_revenue,
     o.loaded_at
 from {{ ref('stg_orders') }} o
-left join {{ ref('dim_customers') }} c on o.order_key = c.customer_key
+-- Fixed join condition: match orders to customers on customer_key, not order_key
+left join {{ ref('dim_customers') }} c on o.customer_key = c.customer_key
 left join items i on o.order_key = i.order_key
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix corrects join key mismatch, restores region_name values, addresses root cause without masking data.
