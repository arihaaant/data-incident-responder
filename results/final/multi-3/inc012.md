# Incident inc012

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `model.tpch_warehouse.stg_orders` error: Compilation Error in model stg_orders (models/staging/stg_orders.sql)

## Diagnosis

- **Started at:** `model.stg_orders`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`

**Evidence**

stg_orders model selects o_orderdate as order_date without casting, leaving it as VARCHAR. The contract expects DATE, causing a compilation error. profile_column on raw.orders.o_orderdate shows all 15000 rows are convertible to DATE losslessly (format %m/%d/%Y). Thus the problem originates from the model's SQL, not the source data. Updating stg_orders.sql to cast o_orderdate to DATE will resolve the contract mismatch.

**Column profile** `raw.orders.o_orderdate` (varchar to date): converts without loss

## What was done

Proposed a change to `models/staging/stg_orders.sql`. The contract for stg_orders expects order_date to be a DATE, but the source column o_orderdate is VARCHAR. All rows are convertible using the format %m/%d/%Y. Updated the model to cast o_orderdate to DATE with strptime(trim(o_orderdate), '%m/%d/%Y')::date, preserving all other columns and types.

```diff
--- a/models/staging/stg_orders.sql
+++ b/models/staging/stg_orders.sql
@@ -3,7 +3,7 @@
     o_custkey as customer_key,
     o_orderstatus as order_status,
     o_totalprice as total_price,
-    o_orderdate as order_date,
+    strptime(trim(o_orderdate), '%m/%d/%Y')::date as order_date,
     o_orderpriority as priority,
     _loaded_at as loaded_at
 from {{ source('raw', 'orders') }}
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix correctly casts source VARCHAR to DATE using lossless conversion as indicated by profile; resolves contract mismatch without data loss.
