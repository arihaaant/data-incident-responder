**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `unique_dim_customers_customer_key` fail (1500 rows): Got 1500 results, configured to fail if != 0

## Diagnosis

- **Started at:** `model.dim_customers`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`

**Evidence**

stg_customers has 1500 rows, distinct customer_key 1500; dim_customers has 7500 rows, distinct keys 1500, indicating each customer duplicated 5x. dim_customers SQL joins stg_regions with condition 'n.region_key = n.region_key' (always true), causing cartesian join with 5 region rows. Fix join to 'r.region_key = n.region_key' to eliminate duplication.

## What was done

Proposed a change to `models/marts/dim_customers.sql`. Fixed the join condition between stg_nations and stg_regions. The original query used `n.region_key = n.region_key`, which is always true and caused a cartesian product, duplicating each customer for every region. Updated to `n.region_key = r.region_key` to correctly join each nation to its region, eliminating duplicate rows and satisfying the unique customer_key check.

```diff
--- a/models/marts/dim_customers.sql
+++ b/models/marts/dim_customers.sql
@@ -7,4 +7,4 @@
     r.region_name
 from {{ ref('stg_customers') }} c
 join {{ ref('stg_nations') }} n on c.nation_key = n.nation_key
-join {{ ref('stg_regions') }} r on n.region_key = n.region_key
+join {{ ref('stg_regions') }} r on n.region_key = r.region_key
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix corrects the erroneous join condition (n.region_key = n.region_key) to proper key equality (n.region_key = r.region_key), removing the cartesian product that duplicated customers. Addresses root cause without masking data.
