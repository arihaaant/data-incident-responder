# Incident inc003

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `model.tpch_warehouse.stg_orders` error: Runtime Error in model stg_orders (models/staging/stg_orders.sql)

## Diagnosis

- **Started at:** `source.raw.orders`, column `o_order_date`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`, `stg_orders`

**Evidence**

stg_orders model references o_orderdate, but raw.orders table has column o_order_date (underscore). Binder error shows column not found. This is a schema drift due to column rename at source. Policy: renamed column is same data, so fix by patching staging model to use o_order_date. Root cause is source raw.orders.

## What was done

Proposed a change to `models/staging/stg_orders.sql`. The source table raw.orders renamed the column from o_orderdate to o_order_date (underscore). The staging model referenced the old name, causing a binder error. Updated the SELECT to use the correct column name while preserving all other columns and aliases.

```diff
--- a/models/staging/stg_orders.sql
+++ b/models/staging/stg_orders.sql
@@ -3,7 +3,7 @@
     o_custkey as customer_key,
     o_orderstatus as order_status,
     o_totalprice as total_price,
-    o_orderdate as order_date,
+    o_order_date as order_date,
     o_orderpriority as priority,
     _loaded_at as loaded_at
 from {{ source('raw', 'orders') }}
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix correctly updates staging model to reference renamed source column o_order_date, addressing schema drift without masking data.
