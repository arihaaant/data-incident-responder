# Incident inc001

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `model.tpch_warehouse.stg_orders` error: Runtime Error in model stg_orders (models/staging/stg_orders.sql)

## Diagnosis

- **Started at:** `source.raw.orders`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`, `stg_orders`

**Evidence**

raw.orders column list shows o_order_priority (underscore) while stg_orders model selects o_orderpriority (no underscore). Binder error indicates missing column. Updating stg_orders to select o_order_priority as priority resolves the issue.

## What was done

Proposed a change to `models/staging/stg_orders.sql`. The source table raw.orders defines the column as `o_order_priority` (with an underscore). The staging model was incorrectly referencing `o_orderpriority`, causing a binder error. Updated the SELECT to use the correct column name while preserving the alias `priority`. No other changes were made to keep column contracts intact.

```diff
--- a/models/staging/stg_orders.sql
+++ b/models/staging/stg_orders.sql
@@ -4,6 +4,6 @@
     o_orderstatus as order_status,
     o_totalprice as total_price,
     o_orderdate as order_date,
-    o_orderpriority as priority,
+    o_order_priority as priority,
     _loaded_at as loaded_at
 from {{ source('raw', 'orders') }}
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix correctly updates staging model to reference renamed source column o_order_priority, preserving alias and column contract. No masking or data alteration.
