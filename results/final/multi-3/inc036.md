# Incident inc036

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `unique_stg_lineitem_order_line_id` fail (14739 rows): Got 14739 results, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.lineitem`, column `l_orderkey,l_linenumber`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`, `stg_lineitem`

**Evidence**

raw.lineitem has 74,914 rows but only 60,175 distinct order_line_id values (order_key-linenumber). Duplicate groups like (l_orderkey=32, l_linenumber=3) appear twice with identical column values, leading to 14,739 duplicate order_line_id rows in stg_lineitem. Duplicates are exact, indicating a double batch load; deduplication can be applied in the stg_lineitem model.

<details><summary>3 queries run during the investigation</summary>

```sql
SELECT COUNT(*) AS total_rows, COUNT(DISTINCT l_orderkey || '-' || l_linenumber) AS distinct_order_line_id FROM raw.lineitem
```
```sql
SELECT l_orderkey, l_linenumber, COUNT(*) AS cnt FROM raw.lineitem GROUP BY l_orderkey, l_linenumber HAVING COUNT(*) > 1 LIMIT 5
```
```sql
SELECT * FROM raw.lineitem WHERE l_orderkey = 32 AND l_linenumber = 3
```

</details>

## What was done

Proposed a change to `models/staging/stg_lineitem.sql`. Added a CTE that assigns a row_number over each (l_orderkey, l_linenumber) group and filters to keep only the first row (rn = 1). This removes the exact duplicate rows caused by a double batch load while preserving all original columns, their order, and data types.

```diff
--- a/models/staging/stg_lineitem.sql
+++ b/models/staging/stg_lineitem.sql
@@ -1,3 +1,18 @@
+with deduped as (
+    select
+        l_orderkey,
+        l_linenumber,
+        l_partkey,
+        l_suppkey,
+        l_quantity,
+        l_extendedprice,
+        l_discount,
+        l_tax,
+        l_returnflag,
+        l_shipdate,
+        row_number() over (partition by l_orderkey, l_linenumber order by l_orderkey) as rn
+    from {{ source('raw', 'lineitem') }}
+)
 select
     l_orderkey || '-' || l_linenumber as order_line_id,
     l_orderkey as order_key,
@@ -11,4 +26,5 @@
     l_returnflag as return_flag,
     l_shipdate as ship_date,
     l_extendedprice * (1 - l_discount) as net_revenue
-from {{ source('raw', 'lineitem') }}
+from deduped
+where rn = 1
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix correctly deduplicates exact duplicate rows caused by double batch load using row_number partition; no type/format changes involved and duplicates are exact, so the patch resolves the root cause without masking data.
