## What broke

- `assert_orders_fresh` fail (1 rows): Got 1 result, configured to fail if != 0
- `relationships_stg_lineitem_order_key__order_key__ref_stg_orders_` fail (230 rows): Got 230 results, configured to fail if != 0

## Diagnosis

- **Started at:** `model.stg_orders`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`

**Evidence**

stg_orders model filters out recent orders using `where o_orderdate < (select max(o_orderdate) from raw.orders) - interval 7 day`. Raw orders count is 15000, but stg_orders has 14941 rows, missing the latest 59 orders. This causes the freshness check to see 1 stale row and the relationship check to report 230 orphan lineitem rows (lineitem rows reference order keys that were filtered out). The filter is unnecessary/incorrect, so fixing the model (removing the date filter) will restore the missing orders and resolve both failing checks.

## What was done

Proposed a change to `models/staging/stg_orders.sql`. The original model filtered out orders where `o_orderdate` was within the last 7 days, causing recent orders to be missing. This led to freshness and relationship checks failing. The filter was unnecessary, so it has been removed, restoring all orders while keeping column names and types unchanged.

```diff
--- a/models/staging/stg_orders.sql
+++ b/models/staging/stg_orders.sql
@@ -7,4 +7,4 @@
     o_orderpriority as priority,
     _loaded_at as loaded_at
 from {{ source('raw', 'orders') }}
-where o_orderdate < (select max(o_orderdate) from {{ source('raw', 'orders') }}) - interval 7 day
+-- Removed erroneous date filter that excluded the most recent 7 days of orders.
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix removes erroneous date filter, restoring missing recent orders and resolving freshness and relationship failures. No data masking or column changes; addresses root cause directly.
