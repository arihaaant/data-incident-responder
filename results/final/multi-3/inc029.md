# Incident inc029

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `not_null_stg_orders_order_date` fail (363 rows): Got 363 results, configured to fail if != 0

## Diagnosis

- **Started at:** `model.stg_orders`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`

**Evidence**

raw.orders has 0 null order_date values (SELECT COUNT(o_orderdate) shows none). stg_orders model sets order_date to NULL for rows where o_orderstatus = 'P' via CASE expression, resulting in 363 nulls matching failing test. The nulls are introduced by the model, not upstream data.

<details><summary>2 queries run during the investigation</summary>

```sql
SELECT COUNT(*) AS total_rows, COUNT(order_date) AS not_null_rows FROM raw.orders
```
```sql
SELECT COUNT(*) AS total, SUM(CASE WHEN o_orderstatus = 'P' THEN 1 ELSE 0 END) AS p_status, SUM(CASE WHEN o_orderstatus = 'P' AND o_orderdate IS NULL THEN 1 ELSE 0 END) AS p_null_date FROM raw.orders
```

</details>

## What was done

Proposed a change to `models/staging/stg_orders.sql`. Removed the CASE expression that set order_date to NULL for rows where o_orderstatus = 'P'. The source data has no null order_date values, and the not_null test expects all rows to have a value. By directly selecting o_orderdate, we preserve the original non-null dates and satisfy the test while keeping column names and types unchanged.

```diff
--- a/models/staging/stg_orders.sql
+++ b/models/staging/stg_orders.sql
@@ -3,7 +3,7 @@
     o_custkey as customer_key,
     o_orderstatus as order_status,
     o_totalprice as total_price,
-    case when o_orderstatus <> 'P' then o_orderdate end as order_date,
+    o_orderdate as order_date,
     o_orderpriority as priority,
     _loaded_at as loaded_at
 from {{ source('raw', 'orders') }}
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix removes artificial NULL injection by CASE, preserving source order_date as intended. No type/format change, and aligns model with source data. Accept.
