# Incident inc045

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `unique_stg_lineitem_order_line_id` fail (14902 rows): Got 14902 results, configured to fail if != 0

## Diagnosis

- **Started at:** `model.stg_lineitem`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`

**Evidence**

raw.lineitem has 60,175 rows, but staging.stg_lineitem has 75,077 rows (increase). The stg_lineitem model SQL performs a UNION ALL of the raw table with itself, adding a second copy of rows where l_returnflag='R', causing duplicate order_line_id values (14,902 duplicates). The duplicate check fails on stg_lineitem.order_line_id. The issue originates from the model's code, not upstream data.

```sql
SELECT COUNT(*) AS total_rows FROM stg_lineitem
```

```sql
SELECT COUNT(*) AS total_rows FROM staging.stg_lineitem
```

</details>

## What was done

Proposed a change to `models/staging/stg_lineitem.sql`. Removed the erroneous UNION ALL that duplicated rows where l_returnflag = 'R'. The original model unintentionally added a second copy of those rows, causing duplicate order_line_id values and failing the unique check. By selecting from the raw lineitem table only once, we preserve the intended column set and data types while ensuring each order_line_id appears only once.

```diff
--- a/models/staging/stg_lineitem.sql
+++ b/models/staging/stg_lineitem.sql
@@ -12,7 +12,3 @@
     l_shipdate as ship_date,
     l_extendedprice * (1 - l_discount) as net_revenue
 from {{ source('raw', 'lineitem') }}
-union all
-select l_orderkey || '-' || l_linenumber, l_orderkey, l_linenumber, l_partkey, l_suppkey, l_quantity, l_extendedprice, l_discount, l_tax, l_returnflag, l_shipdate, l_extendedprice * (1 - l_discount)
-from {{ source('raw', 'lineitem') }}
-where l_returnflag = 'R'
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix removes erroneous UNION ALL that duplicated rows, addressing the root cause of duplicate order_line_id values. No type or format changes involved.
