- `assert_orders_fresh` fail (1 rows): Got 1 result, configured to fail if != 0
- `relationships_stg_lineitem_order_key__order_key__ref_stg_orders_` fail (801 rows): Got 801 results, configured to fail if != 0

## Diagnosis

- **Started at:** `model.stg_orders`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`

**Evidence**

stg_orders has 14,790 rows vs raw.orders 15,000 rows (210 missing). The stg_orders model filters on o_orderdate < '1998-07-01', dropping all orders on or after that date. stg_lineitem retains all 60,175 rows, so 801 lineitem rows reference order_keys that were filtered out, causing the FK relationship check to fail. The freshness check also fails (1 stale row) because the filter prevents recent orders from being loaded, making the latest loaded_at older than expected. The problem originates in the stg_orders SQL filter, not in the source data.

## What was done

Proposed a change to `models/staging/stg_orders.sql`. The original model filtered orders to only those with o_orderdate before 1998-07-01, which caused 210 orders to be omitted. This broke the foreign key relationship with stg_lineitem (801 orphan lineitems) and caused the freshness check to fail because recent orders were not loaded. By removing the date filter, we load the full orders table, preserving column contracts and ensuring downstream checks pass.

```diff
--- a/models/staging/stg_orders.sql
+++ b/models/staging/stg_orders.sql
@@ -7,4 +7,4 @@
     o_orderpriority as priority,
     _loaded_at as loaded_at
 from {{ source('raw', 'orders') }}
-where o_orderdate < date '1998-07-01'
+-- Removed restrictive date filter to include all orders and satisfy downstream checks
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix removes the erroneous date filter that was dropping valid orders, restoring full row count and fixing FK and freshness failures. No masking or data alteration; aligns staging model with source.
