- `assert_orders_fresh` fail (1 rows): Got 1 result, configured to fail if != 0
- `relationships_stg_lineitem_order_key__order_key__ref_stg_orders_` fail (29165 rows): Got 29165 results, configured to fail if != 0

## Diagnosis

- **Started at:** `model.stg_orders`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`

**Evidence**

raw.orders has 15000 rows, but stg_orders only 7667 rows. The stg_orders model filters out orders with status 'O' (where o_orderstatus <> 'O'), dropping ~7300 rows. This causes many lineitems (29165) to reference missing orders, failing the relationship check, and also triggers the freshness check. The issue originates in the stg_orders model code, not the source data.

## What was done

Proposed a change to `models/staging/stg_orders.sql`. Removed the filter `where o_orderstatus <> 'O'` which was unintentionally dropping orders with status 'O'. This restores the full set of 15,000 source rows, fixing the relationship check between lineitems and orders and the freshness check.

```diff
--- a/models/staging/stg_orders.sql
+++ b/models/staging/stg_orders.sql

```

- **Reviewer:** approved. Fix removes erroneous filter that dropped ~7300 orders, restoring full source row count and fixing relationship and freshness failures. No masking or data alteration; appropriate correction to staging model.
