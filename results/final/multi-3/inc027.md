# Incident inc027

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `not_null_stg_customers_market_segment` fail (288 rows): Got 288 results, configured to fail if != 0

## Diagnosis

- **Started at:** `model.stg_customers`
- **Cause:** a change in a model
- **Downstream models affected:** `dim_customers`, `fct_daily_revenue`, `fct_orders`

**Evidence**

raw.customer has 1500 rows, 288 with c_mktsegment='MACHINERY'. stg_customers model uses nullif(trim(c_mktsegment), 'MACHINERY') which converts those 288 rows to NULL, causing not_null test to fail. The source data has no nulls, so the issue is the model's transformation.

```sql
SELECT COUNT(*) AS total, SUM(CASE WHEN c_mktsegment = 'MACHINERY' THEN 1 ELSE 0 END) AS mach_rows FROM raw.customer
```

</details>

## What was done

Proposed a change to `models/staging/stg_customers.sql`. The not_null test on `market_segment` was failing because the model used `nullif(trim(c_mktsegment), 'MACHINERY')`, which turned any 'MACHINERY' values into NULL. The source data contains no nulls, and the test expects all rows to have a non‑null market segment. Replaced the `nullif` logic with a simple `trim` to preserve the original value while still cleaning whitespace. All other columns and their types remain unchanged.

```diff
--- a/models/staging/stg_customers.sql
+++ b/models/staging/stg_customers.sql
@@ -4,6 +4,6 @@
     c_address as address,
     c_phone as phone,
     c_nationkey as nation_key,
-    nullif(trim(c_mktsegment), 'MACHINERY') as market_segment,
+    trim(c_mktsegment) as market_segment,
     c_acctbal as account_balance
 from {{ source('raw', 'customer') }}
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Patch removes the erroneous nullif that turned valid 'MACHINERY' values into NULL, fixing the not_null test without masking data or altering types. It directly addresses the root cause.
