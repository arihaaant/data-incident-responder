# Incident inc005

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `model.tpch_warehouse.stg_customers` error: Runtime Error in model stg_customers (models/staging/stg_customers.sql)

## Diagnosis

- **Started at:** `source.raw.customer`, column `c_account_balance`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `dim_customers`, `fct_daily_revenue`, `fct_orders`, `stg_customers`

**Evidence**

raw.customer table now has column c_account_balance instead of c_acctbal; stg_customers model still selects c_acctbal causing binder error. Schema drift identified; rename column in staging model to c_account_balance.

## What was done

Proposed a change to `models/staging/stg_customers.sql`. The upstream raw.customer table renamed the balance column from c_acctbal to c_account_balance. The staging model stg_customers still referenced the old name, causing a binder error. Updated the SELECT to use c_account_balance while preserving the alias 'account_balance' and all other columns unchanged, maintaining the original schema contracts.

```diff
--- a/models/staging/stg_customers.sql
+++ b/models/staging/stg_customers.sql
@@ -5,5 +5,5 @@
     c_phone as phone,
     c_nationkey as nation_key,
     c_mktsegment as market_segment,
-    c_acctbal as account_balance
+    c_account_balance as account_balance
 from {{ source('raw', 'customer') }}
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix correctly updates the staging model to reference the renamed source column c_account_balance, preserving the original alias and schema. No type/format conversion is involved, so lack of a column profile is acceptable.
