# Incident inc009

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `model.tpch_warehouse.stg_lineitem` error: Runtime Error in model stg_lineitem (models/staging/stg_lineitem.sql)

## Diagnosis

- **Started at:** `source.raw.lineitem`, column `l_shipdate`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`, `stg_lineitem`

**Evidence**

The raw.lineitem table has column l_ship_date (DATE) but not l_shipdate. The staging model stg_lineitem references l_shipdate, causing a binder error. This is a schema drift due to column rename. Policy: renamed column carries same data, so patch the staging model to use l_ship_date. Root cause is the source schema change.

<details><summary>1 queries run during the investigation</summary>

```sql
SELECT column_name, data_type FROM information_schema.columns WHERE table_schema='raw' AND table_name='lineitem'
```

</details>

## What was done

Proposed a change to `models/staging/stg_lineitem.sql`. The source table raw.lineitem renamed the ship date column from l_shipdate to l_ship_date. The staging model referenced the old name, causing a binder error. Updated the model to use the correct column name while preserving all other columns and calculations.

```diff
--- a/models/staging/stg_lineitem.sql
+++ b/models/staging/stg_lineitem.sql
@@ -9,6 +9,6 @@
     l_discount as discount,
     l_tax as tax,
     l_returnflag as return_flag,
-    l_shipdate as ship_date,
+    l_ship_date as ship_date,
     l_extendedprice * (1 - l_discount) as net_revenue
 from {{ source('raw', 'lineitem') }}
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Patch correctly updates the staging model to reference the renamed source column l_ship_date, fixing the binder error caused by schema drift. No type/format conversion is involved, so lack of column profile is acceptable.
