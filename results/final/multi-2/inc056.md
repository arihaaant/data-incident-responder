# Incident inc056

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `assert_orders_fresh` fail (1 rows): Got 1 result, configured to fail if != 0
- `relationships_stg_lineitem_order_key__order_key__ref_stg_orders_` fail (1225 rows): Got 1225 results, configured to fail if != 0

## Diagnosis

- **Started at:** `model.stg_orders`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`

**Evidence**

raw.orders has 15000 rows, but stg_orders only 14681 rows (319 missing). The stg_orders model applies a static filter where _loaded_at < date '1998-06-15', dropping recent orders. This causes the freshness check to fail (1 stale row) and the relationship test to find 1225 lineitem rows with order_key not present in stg_orders. The raw data itself is complete, so the issue originates from the stg_orders SQL filter.


```sql
SELECT COUNT(DISTINCT order_key) as distinct_orders FROM raw.orders;
```

## What was done

Proposed a change to `models/staging/stg_orders.sql`. The original model filtered out rows where `_loaded_at` was after 1998-06-15, causing missing orders and failing freshness and relationship checks. Removing the static date filter ensures all orders are loaded, fixing the failing checks while preserving column names and types.

```diff
--- a/models/staging/stg_orders.sql
+++ b/models/staging/stg_orders.sql
@@ -7,4 +7,4 @@
     o_orderpriority as priority,
     _loaded_at as loaded_at
 from {{ source('raw', 'orders') }}
-where _loaded_at < date '1998-06-15'
+-- Removed static filter on _loaded_at to include all orders
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix removes erroneous static _loaded_at filter, restoring missing rows and satisfying freshness and relationship tests. No data masking or type changes involved.
