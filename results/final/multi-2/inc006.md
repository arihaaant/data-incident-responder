# Incident inc006

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `model.tpch_warehouse.stg_customers` error: Runtime Error in model stg_customers (models/staging/stg_customers.sql)

## Diagnosis

- **Started at:** `source.raw.customer`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `dim_customers`, `fct_daily_revenue`, `fct_orders`, `stg_customers`

**Evidence**

Binder error in stg_customers model: column c_nationkey referenced but raw.customer now provides c_nation_key. get_model_sql shows reference to c_nationkey. get_lineage shows upstream raw.customer. The raw source column rename is the first point of failure.

## What was done

Proposed a change to `models/staging/stg_customers.sql`. The upstream source raw.customer renamed the column from c_nationkey to c_nation_key. Updated the reference in the staging model to match the new column name while preserving all other columns and aliases.

```diff
--- a/models/staging/stg_customers.sql
+++ b/models/staging/stg_customers.sql
@@ -3,7 +3,7 @@
     c_name as customer_name,
     c_address as address,
     c_phone as phone,
-    c_nationkey as nation_key,
+    c_nation_key as nation_key,
     c_mktsegment as market_segment,
     c_acctbal as account_balance
 from {{ source('raw', 'customer') }}
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix correctly updates the staging model to use the renamed source column c_nation_key, preserving all other logic. No type/format conversion is involved, so lack of column profile is acceptable.
