# Incident inc042

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `unique_dim_customers_customer_key` fail (1500 rows): Got 1500 results, configured to fail if != 0

## Diagnosis

- **Started at:** `model.dim_customers`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`

**Evidence**

stg_customers has 1500 rows with 1500 distinct customer_key (no duplicates). dim_customers has 7500 rows but only 1500 distinct customer_key, indicating each key appears 5 times. The dim_customers model joins stg_customers to stg_nations correctly, but the join to stg_regions uses `on n.region_key = n.region_key` (always true) instead of `on r.region_key = n.region_key`, causing a cross join with 5 region rows and multiplying each customer row by 5, creating duplicate customer_key rows. Fix the join condition.

## What was done

Proposed a change to `models/marts/dim_customers.sql`. Fixed the join condition to correctly link regions to nations using r.region_key = n.region_key instead of the always-true n.region_key = n.region_key, eliminating the unintended cross join that duplicated customer_key rows.

```diff
--- a/models/marts/dim_customers.sql
+++ b/models/marts/dim_customers.sql
@@ -7,4 +7,4 @@
     r.region_name
 from {{ ref('stg_customers') }} c
 join {{ ref('stg_nations') }} n on c.nation_key = n.nation_key
-join {{ ref('stg_regions') }} r on n.region_key = n.region_key
+join {{ ref('stg_regions') }} r on r.region_key = n.region_key
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix corrects the join condition to r.region_key = n.region_key, removing the cross join that duplicated customer_key rows. Addresses the root cause without masking data.
