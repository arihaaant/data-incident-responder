**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `not_null_fct_orders_region_name` fail (14625 rows): Got 14625 results, configured to fail if != 0

## Diagnosis

- **Started at:** `model.fct_orders`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`

**Evidence**

The not_null test on fct_orders.region_name fails with 14,625 nulls. dim_customers has no null region_name, but the join in fct_orders uses o.order_key = c.customer_key, which mismatches keys (order_key vs customer_key). This results in most rows not finding a matching customer, producing null region_name. Fixing the join to o.customer_key = c.customer_key will resolve the nulls.

## What was done

Proposed a change to `models/marts/fct_orders.sql`. The not_null test on fct_orders.region_name was failing because the join to dim_customers used the wrong key (order_key = customer_key). This caused most rows to have no matching customer, resulting in null region_name. Updated the join to correctly use o.customer_key = c.customer_key while leaving all other logic unchanged.

```diff
--- a/models/marts/fct_orders.sql
+++ b/models/marts/fct_orders.sql
@@ -20,5 +20,6 @@
     coalesce(i.net_revenue, 0) as net_revenue,
     o.loaded_at
 from {{ ref('stg_orders') }} o
-left join {{ ref('dim_customers') }} c on o.order_key = c.customer_key
+-- Fixed join condition: match on customer_key rather than order_key
+left join {{ ref('dim_customers') }} c on o.customer_key = c.customer_key
 left join items i on o.order_key = i.order_key
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix corrects join key mismatch causing null region_name; addresses root cause without masking data.
