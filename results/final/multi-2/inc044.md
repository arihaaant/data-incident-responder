**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `assert_daily_revenue_one_row_per_region` fail (3659 rows): Got 3659 results, configured to fail if != 0

## Diagnosis

- **Started at:** `model.fct_daily_revenue`
- **Cause:** a change in a model

**Evidence**

fct_daily_revenue groups by order_date, region_name, priority, producing multiple rows per region per day. The test expects one row per region per day. Removing priority from GROUP BY will fix duplicates.

## What was done

Proposed a change to `models/marts/fct_daily_revenue.sql`. Removed `priority` from the GROUP BY clause. The model originally grouped by order_date, region_name, and priority, which produced multiple rows per region per day when priority varied. The test `assert_daily_revenue_one_row_per_region` expects a single row per region per day, so eliminating `priority` from the grouping resolves the duplicate rows while preserving the original columns and their types.

```diff
--- a/models/marts/fct_daily_revenue.sql
+++ b/models/marts/fct_daily_revenue.sql
@@ -4,4 +4,4 @@

-group by order_date, region_name, priority
+group by order_date, region_name
```

- **Reviewer:** approved. Fix correctly addresses duplicate rows by removing non‑required priority from GROUP BY, aligning model output with test expectations without masking data or altering column semantics.
