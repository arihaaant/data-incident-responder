# Incident inc041

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `unique_stg_orders_order_key` fail (363 rows): Got 363 results, configured to fail if != 0

## Diagnosis

- **Started at:** `model.stg_orders`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`

**Evidence**

stg_orders model unions raw.orders with itself, duplicating rows where o_orderstatus='P'. This creates 363 duplicate order_key values, causing unique_stg_orders_order_key check to fail. Raw.orders has unique o_orderkey.

<details><summary>1 queries run during the investigation</summary>

```sql
SELECT COUNT(*) AS total_rows, COUNT(DISTINCT order_key) AS distinct_keys FROM raw.orders
```

</details>

## What was done

Proposed a change to `models/staging/stg_orders.sql`. Removed the erroneous UNION ALL that duplicated rows where o_orderstatus = 'P'. The staging model now selects each order exactly once, preserving the original column list and types, which resolves the unique_stg_orders_order_key check failure.

```diff
--- a/models/staging/stg_orders.sql
+++ b/models/staging/stg_orders.sql
@@ -7,7 +7,3 @@
     o_orderpriority as priority,
     _loaded_at as loaded_at
 from {{ source('raw', 'orders') }}
-union all
-select o_orderkey, o_custkey, o_orderstatus, o_totalprice, o_orderdate, o_orderpriority, _loaded_at
-from {{ source('raw', 'orders') }}
-where o_orderstatus = 'P'
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix removes erroneous UNION ALL that duplicated rows, restoring uniqueness of order_key as required. No type/format changes involved.
