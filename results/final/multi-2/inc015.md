# Incident inc015

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `model.tpch_warehouse.stg_nations` error: Runtime Error in model stg_nations (models/staging/stg_nations.sql)

## Diagnosis

- **Started at:** `source.raw.nation`, column `n_region_key`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `dim_customers`, `fct_daily_revenue`, `fct_orders`, `stg_nations`

**Evidence**

The raw.nation table has column n_region_key (underscore) while stg_nations model selects n_regionkey (no underscore), causing binder error. This schema drift originates from source change; fixing by updating the model to reference n_region_key resolves it.

## What was done

Proposed a change to `models/staging/stg_nations.sql`. The source table raw.nation renamed the column from n_regionkey to n_region_key (underscore). The staging model was still selecting n_regionkey, causing a binder error. Updated the model to reference the correct column name n_region_key while preserving column aliases and types. No other changes were made.

```diff
--- a/models/staging/stg_nations.sql
+++ b/models/staging/stg_nations.sql
@@ -1,5 +1,5 @@
 select
     n_nationkey as nation_key,
     n_name as nation_name,
-    n_regionkey as region_key
+    n_region_key as region_key
 from {{ source('raw', 'nation') }}
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix correctly updates the model to reference the renamed source column n_region_key, addressing the schema drift without masking data.
