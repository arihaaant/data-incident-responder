# Incident inc016

**Status:** Escalated to the owner of raw.customer. Nothing was changed.

## What broke

- `not_null_stg_customers_market_segment` fail (375 rows): Got 375 results, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.customer`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `dim_customers`, `fct_daily_revenue`, `fct_orders`, `stg_customers`

**Evidence**

raw.customer has 1500 rows with 375 null c_mktsegment values (SELECT COUNT(*) total, SUM(CASE WHEN c_mktsegment IS NULL THEN 1 ELSE 0 END) nulls). stg_customers simply maps c_mktsegment to market_segment, so nulls propagate, causing not_null test failure.

```sql
SELECT COUNT(*) AS total, SUM(CASE WHEN c_mktsegment IS NULL THEN 1 ELSE 0 END) AS nulls FROM raw.customer
```

</details>

No change was made to the warehouse. The data has to be corrected where it comes from.
