# Incident inc061

**Status:** Escalated to the owner of raw.lineitem. Nothing was changed.

## What broke

- `model.tpch_warehouse.stg_lineitem` error: Compilation Error in model stg_lineitem (models/staging/stg_lineitem.sql)

## Diagnosis

- **Started at:** `source.raw.lineitem`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`, `stg_lineitem`

**Evidence**

stg_lineitem contract expects extended_price DECIMAL(15,2) and net_revenue DECIMAL(18,4). The model selects l_extendedprice (BIGINT) and computes net_revenue from it. profile_column on raw.lineitem.l_extendedprice shows source type BIGINT, lossless=false, all values have zero decimal places, meaning source stopped providing cents. The contract mismatch cannot be fixed by a simple cast without inventing data, so the schema drift originates in the raw source table.

**Column profile** `raw.lineitem.l_extendedprice` (bigint to decimal(15,2)): would lose data: no value has a fractional part although the contract keeps 2 decimal places; if the source used to send fractions, they were dropped before arriving

<details><summary>1 queries run during the investigation</summary>

```sql
SELECT typeof(l_extendedprice * (1 - l_discount)) AS type, COUNT(*) FROM raw.lineitem
```

</details>

## What was done

No change was made to the warehouse. The data has to be corrected where it comes from.
