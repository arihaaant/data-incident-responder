# Incident inc026

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `not_null_stg_lineitem_extended_price` fail (29778 rows): Got 29778 results, configured to fail if != 0

## Diagnosis

- **Started at:** `model.stg_lineitem`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`

**Evidence**

The not_null test on stg_lineitem_extended_price failed with 29,778 nulls. raw.lineitem has 60,175 rows, with l_returnflag='N' for 30,397 rows. The stg_lineitem model computes extended_price as `case when l_returnflag = 'N' then l_extendedprice end`, which returns NULL for all rows where l_returnflag != 'N' (60,175 - 30,397 = 29,778). This exactly matches the failing row count, showing the nulls are introduced by the model's SQL, not by missing source data. The issue started at the stg_lineitem model, so a code patch to set extended_price unconditionally (or adjust the case logic) will fix the test.

```sql
SELECT COUNT(*) AS cnt FROM raw.lineitem
```
```sql
SELECT l_returnflag, COUNT(*) AS cnt FROM raw.lineitem GROUP BY l_returnflag
```

</details>

## What was done

Proposed a change to `models/staging/stg_lineitem.sql`. Replaced the conditional CASE expression for `extended_price` with a direct reference to `l_extendedprice`. The original logic returned NULL for rows where `l_returnflag` != 'N', causing 29,778 nulls and failing the not_null test. By assigning `l_extendedprice` unconditionally, the column now contains a value for every row, satisfying the not_null constraint while preserving the original column name and data type.

```diff
--- a/models/staging/stg_lineitem.sql
+++ b/models/staging/stg_lineitem.sql
@@ -5,7 +5,7 @@
     l_partkey as part_key,
     l_suppkey as supplier_key,
     l_quantity as quantity,
-    case when l_returnflag = 'N' then l_extendedprice end as extended_price,
+    l_extendedprice as extended_price,
     l_discount as discount,
     l_tax as tax,
     l_returnflag as return_flag,
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix corrects the root cause by removing the conditional that introduced NULLs; it restores the original column values without masking or altering data semantics. No type/format changes involved, so the patch is appropriate.
