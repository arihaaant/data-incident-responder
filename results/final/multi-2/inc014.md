# Incident inc014

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `model.tpch_warehouse.stg_parts` error: Runtime Error in model stg_parts (models/staging/stg_parts.sql)

## Diagnosis

- **Started at:** `source.raw.part`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`, `stg_parts`

**Evidence**

Binder error in model stg_parts: column p_brand not found. raw.part schema lists p_brand_name instead, indicating a column rename. The staging model must be updated to reference p_brand_name, fixing the schema drift.

## What was done

Proposed a change to `models/staging/stg_parts.sql`. The upstream raw.part source renamed the column `p_brand` to `p_brand_name`. The staging model `stg_parts` still referenced the old name, causing a binder error. Updated the SELECT to use `p_brand_name` while preserving the original alias `brand`. All other column references and aliases remain unchanged, maintaining the expected schema and data types.

```diff
--- a/models/staging/stg_parts.sql
+++ b/models/staging/stg_parts.sql
@@ -1,7 +1,7 @@
 select
     p_partkey as part_key,
     p_name as part_name,
-    p_brand as brand,
+    p_brand_name as brand,
     p_type as part_type,
     p_retailprice as retail_price
 from {{ source('raw', 'part') }}
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix correctly updates reference to renamed column p_brand_name, preserving alias and schema. No type/format conversion involved, so lack of column profile is acceptable.
