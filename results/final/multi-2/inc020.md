# Incident inc020

**Status:** Escalated to the owner of raw.orders. Nothing was changed.

## What broke

- `not_null_stg_orders_order_date` fail (750 rows): Got 750 results, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.orders`, column `o_orderdate`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`, `stg_orders`

**Evidence**

raw.orders has 750 null values in o_orderdate (SELECT COUNT(*) FILTER (WHERE o_orderdate IS NULL) FROM raw.orders returns 750). stg_orders model directly maps o_orderdate to order_date without alteration, so nulls flow downstream, causing not_null_stg_orders_order_date test to fail.

```sql
SELECT COUNT(*) AS total_rows, COUNT(*) FILTER (WHERE order_date IS NULL) AS null_rows FROM raw.orders
```
```sql
SELECT COUNT(*) AS total_rows, COUNT(*) FILTER (WHERE o_orderdate IS NULL) AS null_rows FROM raw.orders
```

</details>

## What was done

No change was made to the warehouse. The data has to be corrected where it comes from.
