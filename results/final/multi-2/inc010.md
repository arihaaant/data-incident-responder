# Incident inc010

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `model.tpch_warehouse.stg_lineitem` error: Runtime Error in model stg_lineitem (models/staging/stg_lineitem.sql)

## Diagnosis

- **Started at:** `source.raw.lineitem`, column `l_discount`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`, `stg_lineitem`

**Evidence**

stg_lineitem model fails with binder error on line 15: l_extendedprice * (1 - l_discount). raw.lineitem.l_discount is VARCHAR while staging contract expects decimal(15,2). profile_column shows conversion to decimal is lossless, so patch stg_lineitem to cast(l_discount as decimal(15,2)) before subtraction.

**Column profile** `raw.lineitem.l_discount` (varchar to decimal(15,2)): converts without loss

## What was done

Proposed a change to `models/staging/stg_lineitem.sql`. The source column `l_discount` is VARCHAR but the staging contract expects `decimal(15,2)`. The column profile shows a lossless conversion to decimal. We cast `l_discount` to `decimal(15,2)` both for the `discount` field and within the `net_revenue` calculation, fixing the binder error while preserving all other columns and types.

```diff
--- a/models/staging/stg_lineitem.sql
+++ b/models/staging/stg_lineitem.sql
@@ -6,9 +6,9 @@
     l_suppkey as supplier_key,
     l_quantity as quantity,
     l_extendedprice as extended_price,
-    l_discount as discount,
+    cast(l_discount as decimal(15,2)) as discount,
     l_tax as tax,
     l_returnflag as return_flag,
     l_shipdate as ship_date,
-    l_extendedprice * (1 - l_discount) as net_revenue
+    l_extendedprice * (1 - cast(l_discount as decimal(15,2))) as net_revenue
 from {{ source('raw', 'lineitem') }}
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Patch correctly casts l_discount to decimal(15,2) per lossless profile and updates net_revenue calculation, fixing binder error without data loss.
