# Incident inc024

**Status:** Escalated to the owner of raw.customer. Nothing was changed.

## What broke

- `not_null_stg_customers_customer_key` fail (60 rows): Got 60 results, configured to fail if != 0
- `relationships_stg_orders_customer_key__customer_key__ref_stg_customers_` fail (600 rows): Got 600 results, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.customer`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `dim_customers`, `fct_daily_revenue`, `fct_orders`, `stg_customers`

**Evidence**

raw.customer table has 1500 rows but only 1440 non-null customer_key values, matching the 60 nulls flagged by not_null_stg_customers_customer_key. stg_customers model directly selects c_custkey as customer_key, so nulls originate from source. raw.orders contains 15000 rows with 15000 non-null o_custkey values but only 1000 distinct keys, while stg_customers provides 1440 distinct keys, causing 600 orphaned order rows in relationships check. Thus the issue starts at raw.customer source data.
