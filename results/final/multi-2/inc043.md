# Incident inc043

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `unique_stg_customers_customer_key` fail (337 rows): Got 337 results, configured to fail if != 0

## Diagnosis

- **Started at:** `model.stg_customers`, column `customer_key`
- **Cause:** a change in a model
- **Downstream models affected:** `dim_customers`, `fct_daily_revenue`, `fct_orders`

**Evidence**

raw.customer has 1500 rows and 1500 distinct c_custkey (no duplicates). stg_customers model SQL selects all rows then UNION ALL the same source plus a filtered subset where c_mktsegment='BUILDING', adding a second copy of each BUILDING customer (337 rows). The uniqueness check reports 337 duplicate customer_key rows, exactly the number of BUILDING customers, confirming the duplication originates from the model's UNION ALL logic.

```sql
SELECT COUNT(*) AS total_rows, COUNT(DISTINCT c_custkey) AS distinct_keys FROM raw.customer
```
```sql
SELECT COUNT(*) AS building_count FROM raw.customer WHERE c_mktsegment = 'BUILDING'
```

</details>

## What was done

Proposed a change to `models/staging/stg_customers.sql`. Removed the erroneous UNION ALL that duplicated rows for customers where c_mktsegment = 'BUILDING'. The original model selected all rows and then added a second copy of the BUILDING segment, causing 337 duplicate customer_key values and failing the unique check. By keeping only the single SELECT from the source, we preserve the required columns and their types while ensuring each customer appears exactly once, satisfying the uniqueness constraint.

```diff
--- a/models/staging/stg_customers.sql
+++ b/models/staging/stg_customers.sql
@@ -7,7 +7,3 @@
     c_mktsegment as market_segment,
     c_acctbal as account_balance
 from {{ source('raw', 'customer') }}
-union all
-select c_custkey, c_name, c_address, c_phone, c_nationkey, c_mktsegment, c_acctbal
-from {{ source('raw', 'customer') }}
-where c_mktsegment = 'BUILDING'
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix removes the intentional duplicate UNION ALL, restoring one row per customer and satisfying the uniqueness check. No masking or data loss; aligns with root cause.
