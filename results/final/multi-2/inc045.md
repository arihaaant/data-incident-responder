# Incident inc045

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `unique_stg_lineitem_order_line_id` fail (14902 rows): Got 14902 results, configured to fail if != 0

## Diagnosis

- **Started at:** `model.stg_lineitem`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`

**Evidence**

raw.lineitem has 60,175 rows, distinct order_line_id = 60,175. stg_lineitem UNION ALL adds a second copy of rows where l_returnflag='R', resulting in 75,077 rows but only 60,175 distinct order_line_id, causing 14,902 duplicates. The duplicate issue originates from the model's UNION ALL logic, not from raw data.

<details><summary>3 queries run during the investigation</summary>

```sql
SELECT COUNT(*) AS total_rows, COUNT(DISTINCT order_line_id) AS distinct_ids FROM raw.lineitem
```
```sql
SELECT COUNT(*) AS raw_rows FROM raw.lineitem
```
```sql
SELECT COUNT(*) AS total_rows, COUNT(DISTINCT order_line_id) AS distinct_ids FROM (SELECT l_orderkey || '-' || l_linenumber as order_line_id FROM raw.lineitem UNION ALL SELECT l_orderkey || '-' || l_linenumber FROM raw.lineitem WHERE l_returnflag = 'R')
```

</details>

## What was done

Proposed a change to `models/staging/stg_lineitem.sql`. Removed the erroneous UNION ALL that re‑added rows where `l_returnflag = 'R'`. The original logic duplicated those rows, causing 14,902 duplicate `order_line_id` values and failing the unique check. Keeping only the single SELECT preserves the intended row set and maintains all column names and types.

```diff
--- a/models/staging/stg_lineitem.sql
+++ b/models/staging/stg_lineitem.sql
@@ -12,7 +12,3 @@

-select l_orderkey || '-' || l_linenumber, l_orderkey, l_linenumber, l_partkey, l_suppkey, l_quantity, l_extendedprice, l_discount, l_tax, l_returnflag, l_shipdate, l_extendedprice * (1 - l_discount)
-from {{ source('raw', 'lineitem') }}
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix removes the erroneous UNION ALL that duplicated rows, directly addressing the duplicate order_line_id issue without masking data or altering column definitions.
