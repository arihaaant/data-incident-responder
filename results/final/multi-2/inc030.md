# Incident inc030

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `not_null_stg_lineitem_discount` fail (5419 rows): Got 5419 results, configured to fail if != 0

## Diagnosis

- **Started at:** `model.stg_lineitem`, column `discount`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`

**Evidence**

stg_lineitem model uses case when l_discount > 0 then l_discount end as discount, turning zero or negative discounts into NULL. Resulting null count 5419 matches failing test. Raw lineitem has no nulls in l_discount, so issue originates from model SQL.

<details><summary>3 queries run during the investigation</summary>

```sql
SELECT COUNT(*) AS total_rows, COUNT(*) FILTER (WHERE discount IS NULL) AS nulls FROM raw.lineitem
```
```sql
SELECT COUNT(*) AS total, COUNT(*) FILTER (WHERE discount IS NULL) AS nulls FROM stg_lineitem
```
```sql
SELECT COUNT(*) AS total, COUNT(*) FILTER (WHERE discount IS NULL) AS nulls FROM staging.stg_lineitem
```

</details>

## What was done

Proposed a change to `models/staging/stg_lineitem.sql`. The failing not_null test on stg_lineitem.discount was caused by the model converting zero or negative discounts to NULL via a CASE expression. Raw data never contains NULLs for l_discount, so the transformation introduced unexpected NULLs (5419 rows). Replaced the CASE expression with a direct mapping of l_discount to the discount column, preserving the original data and type, which resolves the null count and satisfies the not_null check.

```diff
--- a/models/staging/stg_lineitem.sql
+++ b/models/staging/stg_lineitem.sql
@@ -6,7 +6,7 @@
     l_suppkey as supplier_key,
     l_quantity as quantity,
     l_extendedprice as extended_price,
-    case when l_discount > 0 then l_discount end as discount,
+    l_discount as discount,
     l_tax as tax,
     l_returnflag as return_flag,
     l_shipdate as ship_date,
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix directly addresses root cause by removing the CASE that introduced NULLs, preserving original discount values without masking or altering data.
