# Incident inc007

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `model.tpch_warehouse.stg_lineitem` error: Runtime Error in model stg_lineitem (models/staging/stg_lineitem.sql)

## Diagnosis

- **Started at:** `source.raw.lineitem`, column `l_discount_rate`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`, `stg_lineitem`

**Evidence**

The raw.lineitem schema (list_tables) shows column l_discount_rate instead of l_discount. The stg_lineitem model SQL still references l_discount, causing a binder error. This is a schema drift where a source column was renamed. Policy: renamed column carries same data, so fix by patching the staging model to use l_discount_rate.

## What was done

Proposed a change to `models/staging/stg_lineitem.sql`. The source column was renamed from l_discount to l_discount_rate. Updated the staging model to reference the new column name for both the discount field and the net_revenue calculation, preserving the original alias names and column types.

```diff
--- a/models/staging/stg_lineitem.sql
+++ b/models/staging/stg_lineitem.sql
@@ -6,9 +6,9 @@
     l_suppkey as supplier_key,
     l_quantity as quantity,
     l_extendedprice as extended_price,
-    l_discount as discount,
+    l_discount_rate as discount,
     l_tax as tax,
     l_returnflag as return_flag,
     l_shipdate as ship_date,
-    l_extendedprice * (1 - l_discount) as net_revenue
+    l_extendedprice * (1 - l_discount_rate) as net_revenue
 from {{ source('raw', 'lineitem') }}
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix correctly updates staging model to use renamed source column l_discount_rate, preserving semantics and calculations. No type/format conversion needed and no data masking.
