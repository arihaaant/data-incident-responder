## What broke

- `assert_orders_fresh` fail (1 rows): Got 1 result, configured to fail if != 0
- `relationships_stg_lineitem_order_key__order_key__ref_stg_orders_` fail (230 rows): Got 230 results, configured to fail if != 0

## Diagnosis

- **Started at:** `model.stg_orders`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`

**Evidence**

raw.orders contains 15000 rows, but stg_orders only 14941 rows (59 rows missing). The stg_orders model applies a filter: o_orderdate < max(o_orderdate) - interval 7 day, which excludes the most recent 7 days of orders. This causes the freshness check to fail (1 stale row) and creates 230 orphaned lineitem rows (FK relationship failure). The problem originates from the filter logic in the stg_orders model, a code change, and can be fixed by adjusting or removing the date filter.

## What was done

Proposed a change to `models/staging/stg_orders.sql`. The original model filtered out orders where o_orderdate was within the last 7 days, causing missing rows, a freshness failure, and orphaned lineitem rows. By removing the date filter (and adding a comment), we include all orders, preserving column names and types, and resolve the failing checks.

```diff
--- a/models/staging/stg_orders.sql
+++ b/models/staging/stg_orders.sql
@@ -7,4 +7,5 @@
     o_orderpriority as priority,
     _loaded_at as loaded_at
 from {{ source('raw', 'orders') }}
-where o_orderdate < (select max(o_orderdate) from {{ source('raw', 'orders') }}) - interval 7 day
+-- Removed restrictive date filter that excluded the most recent 7 days of orders.
+-- This ensures all orders are staged, satisfying freshness and relationship checks.
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix removes erroneous 7‑day date filter that caused missing recent orders, freshness failures, and orphaned lineitem rows. Restores full dataset without masking or altering data semantics.
