# Incident inc029

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `not_null_stg_orders_order_date` fail (363 rows): Got 363 results, configured to fail if != 0

## Diagnosis

- **Started at:** `model.stg_orders`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`

**Evidence**

raw.orders has 0 null order_date (SELECT COUNT(*) ... null_order_date = 0). stg_orders model sets order_date = CASE WHEN o_orderstatus <> 'P' THEN o_orderdate END, which yields NULL for rows where o_orderstatus = 'P'. There are 363 rows with status 'P' in raw.orders, matching the failing check count. Therefore the nulls are introduced by the model logic, not upstream data.

<details><summary>3 queries run during the investigation</summary>

```sql
SELECT COUNT(*) AS total_rows, SUM(CASE WHEN order_date IS NULL THEN 1 ELSE 0 END) AS null_order_date FROM raw.orders
```
```sql
SELECT COUNT(*) AS total, SUM(CASE WHEN o_orderstatus = 'P' THEN 1 ELSE 0 END) AS p_status FROM raw.orders
```
```sql
SELECT COUNT(*) AS total_rows, SUM(CASE WHEN o_orderdate IS NULL THEN 1 ELSE 0 END) AS null_order_date FROM raw.orders
```

</details>

## What was done

Proposed a change to `models/staging/stg_orders.sql`. The failing not_null check on stg_orders.order_date was caused by the original CASE expression that set order_date to NULL for rows where o_orderstatus = 'P'. Since the source raw.orders has no null order_date values, we can safely propagate the original order date for all rows. Replacing the CASE with a direct mapping to o_orderdate eliminates the introduced nulls while preserving the column type and all other columns unchanged.

```diff
--- a/models/staging/stg_orders.sql
+++ b/models/staging/stg_orders.sql
@@ -3,7 +3,7 @@
     o_custkey as customer_key,
     o_orderstatus as order_status,
     o_totalprice as total_price,
-    case when o_orderstatus <> 'P' then o_orderdate end as order_date,
+    o_orderdate as order_date,
     o_orderpriority as priority,
     _loaded_at as loaded_at
 from {{ source('raw', 'orders') }}
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix removes erroneous CASE that introduced NULLs, correctly propagates existing order_date values. No type/format change, and aligns model with source data. Acceptable.
