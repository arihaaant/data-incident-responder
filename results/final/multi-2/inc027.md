# Incident inc027

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `not_null_stg_customers_market_segment` fail (288 rows): Got 288 results, configured to fail if != 0

## Diagnosis

- **Started at:** `model.stg_customers`
- **Cause:** a change in a model
- **Downstream models affected:** `dim_customers`, `fct_daily_revenue`, `fct_orders`

**Evidence**

The not_null test on stg_customers.market_segment failed with 288 nulls. raw.customer has 1500 rows, with exactly 288 rows where c_mktsegment = 'MACHINERY'. The stg_customers model uses nullif(trim(c_mktsegment), 'MACHINERY') for market_segment, turning those 'MACHINERY' values into NULL. Therefore the nulls are introduced by the model's SQL, not by upstream data. Fix by removing or adjusting the nullif logic.

<details><summary>2 queries run during the investigation</summary>

```sql
SELECT COUNT(*) AS total_rows, SUM(CASE WHEN market_segment IS NULL THEN 1 ELSE 0 END) AS null_market_segment FROM raw.customer
```
```sql
SELECT COUNT(*) AS total, SUM(CASE WHEN c_mktsegment = 'MACHINERY' THEN 1 ELSE 0 END) AS mach_rows FROM raw.customer
```

</details>

## What was done

Proposed a change to `models/staging/stg_customers.sql`. Removed the nullif() that was converting the string 'MACHINERY' to NULL for market_segment. The not_null test expects every market_segment to be populated. By simply trimming the source value we retain the original 'MACHINERY' values (and any others) while still cleaning whitespace, eliminating the 288 nulls introduced by the previous logic.

```diff
--- a/models/staging/stg_customers.sql
+++ b/models/staging/stg_customers.sql
@@ -4,6 +4,6 @@
     c_address as address,
     c_phone as phone,
     c_nationkey as nation_key,
-    nullif(trim(c_mktsegment), 'MACHINERY') as market_segment,
+    trim(c_mktsegment) as market_segment,
     c_acctbal as account_balance
 from {{ source('raw', 'customer') }}
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix removes nullif that incorrectly turned valid 'MACHINERY' values into NULL, restoring original data and satisfying not_null test without masking or data loss.
