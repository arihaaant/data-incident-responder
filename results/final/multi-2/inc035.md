# Incident inc035

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `unique_stg_lineitem_order_line_id` fail (5639 rows): Got 5639 results, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.lineitem`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`, `stg_lineitem`

**Evidence**

raw.lineitem has 65814 rows but only 60175 distinct order_line_id (orderkey-linenumber). Group by shows duplicate (orderkey=96, linenumber=2) with identical values. Stg_lineitem builds order_line_id from these columns, so duplicates flow downstream causing unique check to fail (5639 duplicates). Duplicates are identical across all columns, indicating batch delivered twice; can be fixed by deduplication in stg_lineitem.

## What was done

Proposed a change to `models/staging/stg_lineitem.sql`. Added a CTE to pull the raw source and applied a QUALIFY with ROW_NUMBER() partitioned by the natural duplicate key (orderkey + linenumber). This removes the exact duplicate rows that were delivered twice, ensuring each order_line_id appears only once while preserving all original columns and their data types.

```diff
--- a/models/staging/stg_lineitem.sql
+++ b/models/staging/stg_lineitem.sql
@@ -1,3 +1,8 @@
+with raw_lineitem as (
+    select *
+    from {{ source('raw', 'lineitem') }}
+)
+
 select
     l_orderkey || '-' || l_linenumber as order_line_id,
     l_orderkey as order_key,
@@ -11,4 +16,5 @@
     l_returnflag as return_flag,
     l_shipdate as ship_date,
     l_extendedprice * (1 - l_discount) as net_revenue
-from {{ source('raw', 'lineitem') }}
+from raw_lineitem
+qualify row_number() over (partition by l_orderkey, l_linenumber) = 1
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix correctly deduplicates exact duplicate rows delivered twice, preserving all columns and data types. No masking or data loss; appropriate for upstream duplicate issue.
