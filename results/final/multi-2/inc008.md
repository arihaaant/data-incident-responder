# Incident inc008

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `model.tpch_warehouse.stg_lineitem` error: Runtime Error in model stg_lineitem (models/staging/stg_lineitem.sql)

## Diagnosis

- **Started at:** `source.raw.lineitem`, column `l_extendedprice`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`, `stg_lineitem`

**Evidence**

raw.lineitem schema shows column l_extended_price (underscore) not l_extendedprice. stg_lineitem model references l_extendedprice, causing binder error. The source column rename is the first point of failure; updating the staging model to use l_extended_price will fix.

## What was done

Proposed a change to `models/staging/stg_lineitem.sql`. The source table raw.lineitem uses column name `l_extended_price` (with an underscore) instead of the previously referenced `l_extendedprice`. This caused a binder error during model compilation. Updated the staging model to reference the correct column name in both the column selection and the net_revenue calculation, preserving all other column names, aliases, and types.

```diff
--- a/models/staging/stg_lineitem.sql
+++ b/models/staging/stg_lineitem.sql
@@ -5,10 +5,10 @@
     l_partkey as part_key,
     l_suppkey as supplier_key,
     l_quantity as quantity,
-    l_extendedprice as extended_price,
+    l_extended_price as extended_price,
     l_discount as discount,
     l_tax as tax,
     l_returnflag as return_flag,
     l_shipdate as ship_date,
-    l_extendedprice * (1 - l_discount) as net_revenue
+    l_extended_price * (1 - l_discount) as net_revenue
 from {{ source('raw', 'lineitem') }}
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix updates staging model to use renamed source column l_extended_price, addressing binder error. No type/format change, so lack of column profile is acceptable. Patch correctly adapts to source schema.
