# Incident inc001

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `model.tpch_warehouse.stg_orders` error: Runtime Error in model stg_orders (models/staging/stg_orders.sql)

## Diagnosis

- **Started at:** `source.raw.orders`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`, `stg_orders`

**Evidence**

raw.orders schema shows column o_order_priority (underscore) while stg_orders model references o_orderpriority (no underscore). Binder error indicates missing column. The source column rename is upstream data change; fixing by updating stg_orders to use o_order_priority resolves.

## What was done

Proposed a change to `models/staging/stg_orders.sql`. The upstream source column was renamed to include an underscore (o_order_priority). The staging model referenced the old name o_orderpriority, causing a binder error. Updated the SELECT to use the correct column name while preserving all other columns, aliases, and types.

```diff
--- a/models/staging/stg_orders.sql
+++ b/models/staging/stg_orders.sql
@@ -4,6 +4,6 @@
     o_orderstatus as order_status,
     o_totalprice as total_price,
     o_orderdate as order_date,
-    o_orderpriority as priority,
+    o_order_priority as priority,
     _loaded_at as loaded_at
 from {{ source('raw', 'orders') }}
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix correctly updates staging model to reference renamed source column o_order_priority, addressing the upstream schema change without masking data.
