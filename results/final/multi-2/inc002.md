# Incident inc002

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `model.tpch_warehouse.stg_orders` error: Runtime Error in model stg_orders (models/staging/stg_orders.sql)

## Diagnosis

- **Started at:** `source.raw.orders`, column `o_customer_key`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`, `stg_orders`

**Evidence**

stg_orders model references o_custkey which no longer exists; raw.orders table shows column renamed to o_customer_key. The failing check error confirms missing column. The issue originates from source column rename, so patch stg_orders to use o_customer_key.

## What was done

Proposed a change to `models/staging/stg_orders.sql`. The source table raw.orders renamed the column from o_custkey to o_customer_key. The staging model stg_orders still referenced the old name, causing a binder error. Updated the SELECT to use o_customer_key while preserving all other column mappings and order, ensuring downstream checks remain unchanged.

```diff
--- a/models/staging/stg_orders.sql
+++ b/models/staging/stg_orders.sql
@@ -1,6 +1,6 @@
 select
     o_orderkey as order_key,
-    o_custkey as customer_key,
+    o_customer_key as customer_key,
     o_orderstatus as order_status,
     o_totalprice as total_price,
     o_orderdate as order_date,
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix correctly updates reference to renamed source column without masking data or altering logic. Rename does not require type/format profile.
