# Incident inc004

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `model.tpch_warehouse.stg_customers` error: Runtime Error in model stg_customers (models/staging/stg_customers.sql)

## Diagnosis

- **Started at:** `model.stg_customers`
- **Cause:** a change in a model
- **Downstream models affected:** `dim_customers`, `fct_daily_revenue`, `fct_orders`

**Evidence**

Raw table raw.customer has column c_market_segment, but stg_customers model selects c_mktsegment, causing compile error. The source schema is correct; the model's SQL is wrong. Updating the model to use c_market_segment fixes the issue.

## What was done

Proposed a change to `models/staging/stg_customers.sql`. The source table raw.customer defines the column as c_market_segment, but the staging model incorrectly referenced c_mktsegment, causing a compile error. Updated the SELECT list to use the correct column name while preserving all other columns and aliases.

```diff
--- a/models/staging/stg_customers.sql
+++ b/models/staging/stg_customers.sql
@@ -4,6 +4,6 @@
     c_address as address,
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix correctly updates the staging model to reference the renamed source column c_market_segment, addressing the compile error without masking data.
