# Incident inc036

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `unique_stg_lineitem_order_line_id` fail (14739 rows): Got 14739 results, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.lineitem`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`, `stg_lineitem`

**Evidence**

raw.lineitem has 74,914 rows but only 60,175 distinct order_line_id (l_orderkey||'-'||l_linenumber). Example duplicates: orderkey 1 linenumber 5 appears twice with identical column values. The staging model stg_lineitem builds order_line_id from these columns, so duplicates flow downstream, causing unique_stg_lineitem_order_line_id check to fail with 14,739 duplicate rows.

## What was done

Proposed a change to `models/staging/stg_lineitem.sql`. Added DISTINCT to the SELECT list to drop exact duplicate rows from the raw.lineitem source. The duplicates were identical across all columns, so removing them does not lose any unique information and resolves the unique_stg_lineitem_order_line_id check failure. Column names and types remain unchanged.

```diff
--- a/models/staging/stg_lineitem.sql
+++ b/models/staging/stg_lineitem.sql
@@ -1,4 +1,5 @@
 select
+    distinct
     l_orderkey || '-' || l_linenumber as order_line_id,
     l_orderkey as order_key,
     l_linenumber as line_number,
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix adds DISTINCT to remove only exact duplicate rows, preserving all unique information and satisfying the unique check without altering column logic or data values.
