# Incident inc019

**Status:** Escalated to the owner of raw.lineitem. Nothing was changed.

## What broke

- `not_null_stg_lineitem_discount` fail (12002 rows): Got 12002 results, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.lineitem`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`, `stg_lineitem`

**Evidence**

The not_null_stg_lineitem_discount test failed with 12002 rows. In raw.lineitem, the l_discount column has 12002 nulls out of 60175 rows (SELECT COUNT(*) total_rows, COUNT(l_discount) not_null_discount, COUNT(*)-COUNT(l_discount) null_discount FROM raw.lineitem). The staging model stg_lineitem simply selects l_discount as discount, so the nulls propagate, causing the test failure. The issue originates in the source data, not in the model SQL.

```sql
SELECT COUNT(*) AS total_rows, COUNT(discount) AS not_null_discount, COUNT(*) - COUNT(discount) AS null_discount FROM raw.lineitem
```
```sql
SELECT COUNT(*) AS total_rows, COUNT(l_discount) AS not_null_discount, COUNT(*) - COUNT(l_discount) AS null_discount FROM raw.lineitem
```

</details>

## What was done

No change was made to the warehouse. The data has to be corrected where it comes from.
