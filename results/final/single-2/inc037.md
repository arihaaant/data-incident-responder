# Incident inc037

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `unique_stg_customers_customer_key` fail (75 rows): Got 75 results, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.customer`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `dim_customers`, `fct_daily_revenue`, `fct_orders`, `stg_customers`

**Evidence**

The unique test on stg_customers.customer_key failed with 75 duplicate rows. Raw.customer has duplicate c_custkey values (e.g., c_custkey=16 appears twice) but the duplicate rows are identical across all columns (distinct_rows=1). This indicates a duplicated batch delivery, not a data conflict. Adding SELECT DISTINCT in the staging model removes the duplicate rows, which resolves the unique test without losing any data.
