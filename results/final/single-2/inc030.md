# Incident inc030

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `not_null_stg_lineitem_discount` fail (5419 rows): Got 5419 results, configured to fail if != 0

## Diagnosis

- **Started at:** `model.stg_lineitem`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`

**Evidence**

The not_null_stg_lineitem_discount test failed because 5,419 rows had discount = 0 in raw.lineitem, but the staging model transformed zero discounts to NULL via `case when l_discount > 0 then l_discount end`. This caused the not_null test to fail. Changing the model to select `l_discount as discount` preserves zero values, making the test pass.

<details><summary>2 queries run during the investigation</summary>

```sql
SELECT COUNT(*) AS total_rows, COUNT(discount) AS non_nulls FROM raw.lineitem
```
```sql
SELECT COUNT(*) AS total, COUNT(*) FILTER (WHERE l_discount IS NULL) AS nulls, COUNT(*) FILTER (WHERE l_discount = 0) AS zeros FROM raw.lineitem
```

</details>
