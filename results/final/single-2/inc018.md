# Incident inc018

**Status:** Escalated to the owner of raw.lineitem. Nothing was changed.

## What broke

- `not_null_stg_lineitem_extended_price` fail (8751 rows): Got 8751 results, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.lineitem`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`, `stg_lineitem`

**Evidence**

The not_null_stg_lineitem_extended_price test failed with 8,751 rows. In stg_lineitem model, extended_price is directly taken from raw.lineitem.l_extendedprice. Querying raw.lineitem shows 8,751 null values in l_extendedprice (total 60,175 rows). Therefore the nulls originate in the source raw table, not in the model code. This is an upstream data issue; the source owner must address missing values.

```sql

```
```sql
SELECT COUNT(*) AS total_rows, COUNT(l_extendedprice) AS not_null, COUNT(*) - COUNT(l_extendedprice) AS nulls FROM raw.lineitem
```

</details>

## What was done

No change was made to the warehouse. The data has to be corrected where it comes from.
