# Incident inc024

**Status:** Escalated to the owner of raw.customer. Nothing was changed.

## What broke

- `not_null_stg_customers_customer_key` fail (60 rows): Got 60 results, configured to fail if != 0
- `relationships_stg_orders_customer_key__customer_key__ref_stg_customers_` fail (600 rows): Got 600 results, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.customer`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `dim_customers`, `fct_daily_revenue`, `fct_orders`, `stg_customers`

**Evidence**

The not_null test on stg_customers.customer_key fails with 60 nulls, which come directly from raw.customer where c_custkey is null (60 rows). The relationships test between stg_orders.customer_key and stg_customers.customer_key fails with 600 rows, and a left join of raw.orders to raw.customer shows 600 orders with o_custkey that have no matching c_custkey. These issues originate in the raw.customer source data, not in any dbt model code.
