# Incident inc038

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `unique_stg_customers_customer_key` fail (225 rows): Got 225 results, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.customer`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `dim_customers`, `fct_daily_revenue`, `fct_orders`, `stg_customers`

**Evidence**

The unique_stg_customers_customer_key test failed with 225 duplicate customer_key values. raw.customer has 1725 rows but only 1500 distinct c_custkey, indicating duplicate primary keys. Inspection shows duplicate rows (e.g., c_custkey=6) are identical across all columns, matching the policy for identical duplicate deliveries. Deduplicating in the staging model with SELECT DISTINCT resolves the uniqueness violation without losing data.
