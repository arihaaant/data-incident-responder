# Incident inc039

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `unique_stg_parts_part_key` fail (200 rows): Got 200 results, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.part`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`, `stg_parts`

**Evidence**

The unique test on stg_parts.part_key failed with 200 duplicate rows. raw.part contains duplicate p_partkey values (e.g., key 11 appears twice with identical other columns). The staging model currently selects rows directly, propagating duplicates. Since duplicates are exact copies, policy allows deduplication in the staging model. Applying DISTINCT on p_partkey (or all columns) removes the duplicates, and try_patch confirms all tests now pass.
