# Incident inc050

**Status:** Escalated to the owner of raw.orders. Nothing was changed.

## What broke

- `assert_orders_fresh` fail (1 rows): Got 1 result, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.orders`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`, `stg_orders`

**Evidence**

The failing test assert_orders_fresh is attached to stg_orders and checks that recent data is loaded (e.g., loaded_at within the last 30 days). All rows in staging.stg_orders have loaded_at timestamps from the 1990s (e.g., 1996-01-03, 1993-10-15, etc.), far older than the required freshness window. The raw source table raw.orders contains the same old timestamps, confirming that the source data itself is stale. Therefore the issue originates upstream in the source raw.orders, and cannot be fixed by a downstream model patch; the source owner must provide fresh data.
