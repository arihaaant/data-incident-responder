# Incident inc061

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `model.tpch_warehouse.stg_lineitem` error: Compilation Error in model stg_lineitem (models/staging/stg_lineitem.sql)

## Diagnosis

- **Started at:** `model.stg_lineitem`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`

**Evidence**

The stg_lineitem model failed contract checks: extended_price was BIGINT but contract expects DECIMAL(15,2); net_revenue was DECIMAL(35,2) but contract expects DECIMAL(18,4). Source column l_extendedprice is BIGINT, so casting to DECIMAL(15,2) fixes type. The net_revenue expression yields a higher precision; casting to DECIMAL(18,4) aligns with contract. No upstream data issues; the raw lineitem table types are correct. Therefore the issue is a code change in the model, patched by adding appropriate CASTs.

**Column profile** `raw.lineitem.l_extendedprice` (bigint to decimal(15,2)): would lose data: no value has a fractional part although the contract keeps 2 decimal places; if the source used to send fractions, they were dropped before arriving
