## What broke

- `assert_daily_revenue_one_row_per_region` fail (3659 rows): Got 3659 results, configured to fail if != 0

## Diagnosis

- **Started at:** `model.fct_daily_revenue`
- **Cause:** a change in a model

**Evidence**

The failing test assert_daily_revenue_one_row_per_region expects exactly one row per (order_date, region_name). The current fct_daily_revenue model groups by order_date, region_name, priority, producing multiple rows per region per day (one per priority). This caused 3659 duplicate rows, failing the test. Removing priority from the GROUP BY (and SELECT) fixes the duplication.
