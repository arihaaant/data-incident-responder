# Incident inc016

**Status:** Escalated to the owner of raw.customer. Nothing was changed.

## What broke

- `not_null_stg_customers_market_segment` fail (375 rows): Got 375 results, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.customer`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `dim_customers`, `fct_daily_revenue`, `fct_orders`, `stg_customers`

**Evidence**

The not_null test on stg_customers.market_segment failed with 375 rows. The raw source table raw.customer contains 1500 rows, of which 375 have NULL in c_mktsegment. The staging model stg_customers simply selects c_mktsegment as market_segment without any transformation, so the nulls are directly propagated. Since the problem originates in the raw source data, the incident is due to upstream data and must be escalated to the source owner.

```sql
SELECT COUNT(*) AS total_rows, COUNT(market_segment) AS non_null_market_segment FROM raw.customer
```
```sql
SELECT COUNT(*) AS total_rows, SUM(CASE WHEN c_mktsegment IS NULL THEN 1 ELSE 0 END) AS null_market_segment FROM raw.customer
```

</details>

## What was done

No change was made to the warehouse. The data has to be corrected where it comes from.
