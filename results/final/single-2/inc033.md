# Incident inc033

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `unique_stg_orders_order_key` fail (3000 rows): Got 3000 results, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.orders`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`, `stg_orders`

**Evidence**

The unique_stg_orders_order_key test failed with 3000 duplicate rows. Raw.orders contains duplicate rows for the same o_orderkey (e.g., orderkey 32 appears twice with identical column values). The staging model stg_orders selects rows directly, propagating duplicates. Since the duplicate rows are identical, policy allows deduplication in the staging model. Applying SELECT DISTINCT removes the duplicates, and try_patch confirms all tests now pass.
