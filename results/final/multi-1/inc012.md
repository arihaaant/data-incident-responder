# Incident inc012

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `model.tpch_warehouse.stg_orders` error: Compilation Error in model stg_orders (models/staging/stg_orders.sql)

## Diagnosis

- **Started at:** `model.stg_orders`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`

**Evidence**

The contract for stg_orders expects order_date as DATE, but the model selects o_orderdate directly as VARCHAR. profile_column shows raw.orders.o_orderdate can be losslessly converted to DATE (format %m/%d/%Y). Therefore the upstream raw data is correct; the model's SQL needs to cast order_date to DATE to satisfy the contract.

**Column profile** `raw.orders.o_orderdate` (varchar to date): converts without loss

<details><summary>1 queries run during the investigation</summary>

```sql
SELECT * FROM information_schema.columns WHERE table_schema = 'staging' AND table_name = 'stg_orders'
```

</details>

## What was done

Proposed a change to `models/staging/stg_orders.sql`. The contract for stg_orders requires order_date to be a DATE, but the source column o_orderdate is a VARCHAR in the raw data. The column profile shows all 15,000 values can be losslessly parsed using the format %m/%d/%Y. Updated the model to cast o_orderdate to DATE using the provided conversion expression (strptime(trim(o_orderdate), '%m/%d/%Y')::date). All other columns and their types remain unchanged, preserving the original schema and contracts.

```diff
--- a/models/staging/stg_orders.sql
+++ b/models/staging/stg_orders.sql
@@ -3,7 +3,7 @@
     o_custkey as customer_key,
     o_orderstatus as order_status,
     o_totalprice as total_price,
-    o_orderdate as order_date,
+    strptime(trim(o_orderdate), '%m/%d/%Y')::date as order_date,
     o_orderpriority as priority,
     _loaded_at as loaded_at
 from {{ source('raw', 'orders') }}
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix correctly casts VARCHAR order_date to DATE using lossless format identified in profile; addresses root cause without masking data.
