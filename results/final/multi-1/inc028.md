# Incident inc028

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `not_null_fct_orders_region_name` fail (14625 rows): Got 14625 results, configured to fail if != 0

## Diagnosis

- **Started at:** `model.fct_orders`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`

**Evidence**

not_null test on fct_orders.region_name failed with 14625 nulls out of 15000 rows. In fct_orders model, region_name is derived via left join to dim_customers using `on o.order_key = c.customer_key`. This join condition is incorrect; it should join on o.customer_key = c.customer_key. Query `select count(*) from staging.stg_orders o join marts.dim_customers c on o.order_key = c.customer_key` returned only 375 matches, leaving 14625 rows with null region_name. Upstream tables have correct row counts and no nulls, so the problem originates from the join logic in fct_orders model.

## What was done

Proposed a change to `models/marts/fct_orders.sql`. Fixed the join condition between stg_orders and dim_customers. The original model incorrectly joined on o.order_key = c.customer_key, causing region_name to be null for most rows. Updated to the correct relationship o.customer_key = c.customer_key while preserving all other logic and column definitions.
