# Incident inc001

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `model.tpch_warehouse.stg_orders` error: Runtime Error in model stg_orders (models/staging/stg_orders.sql)

## Diagnosis

- **Started at:** `source.raw.orders`, column `o_order_priority`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`, `stg_orders`

**Evidence**

raw.orders table now defines column o_order_priority (underscore) instead of o_orderpriority. stg_orders model selects o_orderpriority, causing binder error. The source schema change is the origin; fixing by updating stg_orders to use o_order_priority resolves without data loss.

## What was done

Proposed a change to `models/staging/stg_orders.sql`. The source table now defines the column as `o_order_priority` (with an underscore) instead of `o_orderpriority`. The staging model referenced the old name, causing a binder error. Updated the SELECT to use the correct column name while preserving all other column mappings and types.

```diff
--- a/models/staging/stg_orders.sql
+++ b/models/staging/stg_orders.sql
@@ -4,6 +4,6 @@
     o_orderstatus as order_status,
     o_totalprice as total_price,
     o_orderdate as order_date,
-    o_orderpriority as priority,
+    o_order_priority as priority,
     _loaded_at as loaded_at
 from {{ source('raw', 'orders') }}
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix correctly updates staging model to use renamed source column o_order_priority, addressing binder error without masking data. No type/format change, so lack of column profile is acceptable.
