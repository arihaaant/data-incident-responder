# Incident inc013

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `model.tpch_warehouse.stg_customers` error: Compilation Error in model stg_customers (models/staging/stg_customers.sql)

## Diagnosis

- **Started at:** `source.raw.customer`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `dim_customers`, `fct_daily_revenue`, `fct_orders`, `stg_customers`

**Evidence**

raw.customer.c_acctbal is VARCHAR but contract expects DECIMAL(15,2). profile_column shows lossless conversion (1500 rows convertible, 0 failures). stg_customers model selects c_acctbal as account_balance without cast, causing contract type mismatch. Adding cast(c_acctbal as DECIMAL(15,2)) in stg_customers will satisfy contract.

**Column profile** `raw.customer.c_acctbal` (varchar to decimal(15,2)): converts without loss

## What was done

Proposed a change to `models/staging/stg_customers.sql`. Added a cast to convert the raw VARCHAR column c_acctbal to the contracted DECIMAL(15,2) type for the account_balance field, satisfying the model's enforced contract without altering any other columns or logic.

```diff
--- a/models/staging/stg_customers.sql
+++ b/models/staging/stg_customers.sql
@@ -5,5 +5,5 @@
     c_phone as phone,
     c_nationkey as nation_key,
     c_mktsegment as market_segment,
-    c_acctbal as account_balance
+    cast(c_acctbal as decimal(15,2)) as account_balance
 from {{ source('raw', 'customer') }}
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Patch correctly casts raw VARCHAR c_acctbal to DECIMAL(15,2) as required by contract. Profile confirms lossless conversion. No data masking or logic changes beyond required type adaptation.
