## Diagnosis

- **Started at:** `model.stg_orders`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`

**Evidence**

stg_orders filters o_orderdate < '1998-07-01', but raw.orders contains dates up to 1998-08-02. This filter drops 210 order keys, causing 801 lineitems to lack matching orders (relationships check fails) and freshness test on orders reports 1 late row. Adjusting/removing the date filter restores expected row counts and passes checks.

## What was done

Proposed a change to `models/staging/stg_orders.sql`. The original model filtered orders to dates before 1998-07-01, but the source data includes orders up to 1998-08-02. This caused missing order keys, breaking the relationships check and freshness test. By removing the date filter (or expanding it to include all dates), we restore the full set of orders, ensuring downstream lineitem relationships and freshness checks pass while keeping column definitions unchanged.

```diff
--- a/models/staging/stg_orders.sql
+++ b/models/staging/stg_orders.sql
@@ -7,4 +7,4 @@
     o_orderpriority as priority,
     _loaded_at as loaded_at
 from {{ source('raw', 'orders') }}
-where o_orderdate < date '1998-07-01'
+-- Removed restrictive date filter to include all order dates
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix removes the restrictive date filter that caused missing order rows, directly addressing the root cause without masking data or altering column definitions.
