# Incident inc059

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `assert_orders_fresh` fail (1 rows): Got 1 result, configured to fail if != 0
- `relationships_stg_lineitem_order_key__order_key__ref_stg_orders_` fail (769 rows): Got 769 results, configured to fail if != 0

## Diagnosis

- **Started at:** `model.stg_orders`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`

**Evidence**

raw.orders has 15000 rows, raw.lineitem has 60175 rows and 15000 distinct order keys. staging.stg_orders has only 14800 rows, missing 200 orders. The stg_orders model filters with `where o_orderdate < date '{{ var("as_of") }}' - interval 30 day'`, which excludes recent orders. Consequently, relationships test finds 769 lineitem rows referencing missing orders, and the freshness check fails (1 stale row). The missing orders are due to the filter, not source data, so the problem started in the stg_orders model code. The fix is to adjust or remove the date filter to include all orders, i.e., patch the stg_orders model.

## What was done

Proposed a change to `models/staging/stg_orders.sql`. Removed the date filter that excluded recent orders. The original filter `where o_orderdate < date '{{ var("as_of") }}' - interval 30 day` caused 200 orders to be omitted, breaking the relationships test and freshness check. By selecting all rows from the raw orders source, we ensure all order keys are present, satisfying downstream constraints while preserving column names and types.

```diff
--- a/models/staging/stg_orders.sql
+++ b/models/staging/stg_orders.sql
@@ -7,4 +7,3 @@
     o_orderpriority as priority,
     _loaded_at as loaded_at
 from {{ source('raw', 'orders') }}
-where o_orderdate < date '{{ var("as_of") }}' - interval 30 day
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Patch correctly removes the date filter that caused missing order rows, restoring full order set and fixing relationship and freshness failures. No data masking or type changes involved.
