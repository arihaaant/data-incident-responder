# Incident inc011

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `model.tpch_warehouse.stg_lineitem` error: Runtime Error in model stg_lineitem (models/staging/stg_lineitem.sql)

## Diagnosis

- **Started at:** `source.raw.lineitem`, column `l_extendedprice`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`, `stg_lineitem`

**Evidence**

raw.lineitem.l_extendedprice is VARCHAR while stg_lineitem expects decimal(15,2). profile_column shows lossless conversion possible. The stg_lineitem model multiplies l_extendedprice * (1 - l_discount) causing type error. Adding cast(l_extendedprice as decimal(15,2)) in the model fixes it.

**Column profile** `raw.lineitem.l_extendedprice` (varchar to decimal(15,2)): converts without loss

## What was done

Proposed a change to `models/staging/stg_lineitem.sql`. The source column `l_extendedprice` is VARCHAR but the staging model expects a DECIMAL(15,2). Added explicit casts to DECIMAL(15,2) for both the `extended_price` field and the calculation of `net_revenue`. This resolves the type mismatch without altering any other columns or logic.

```diff
--- a/models/staging/stg_lineitem.sql
+++ b/models/staging/stg_lineitem.sql
@@ -5,10 +5,10 @@
     l_partkey as part_key,
     l_suppkey as supplier_key,
     l_quantity as quantity,
-    l_extendedprice as extended_price,
+    cast(l_extendedprice as decimal(15,2)) as extended_price,
     l_discount as discount,
     l_tax as tax,
     l_returnflag as return_flag,
     l_shipdate as ship_date,
-    l_extendedprice * (1 - l_discount) as net_revenue
+    cast(l_extendedprice as decimal(15,2)) * (1 - l_discount) as net_revenue
 from {{ source('raw', 'lineitem') }}
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Patch correctly casts varchar l_extendedprice to decimal(15,2) as indicated by lossless column profile, fixing type error without data loss or masking.
