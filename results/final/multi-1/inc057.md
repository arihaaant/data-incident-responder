## Diagnosis

- **Started at:** `model.stg_orders`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`

**Evidence**

stg_orders model filters orders to year(o_orderdate) < 1998, dropping recent orders. raw.orders has 15000 rows, stg_orders only 13654 rows. raw.lineitem has 15000 distinct order keys, but relationships check shows 5315 lineitem rows without matching order, indicating many orders missing. Freshness check fails (1 stale row) because loaded_at dates are old. No issues in raw tables. Therefore the problem started in stg_orders due to an incorrect filter; patch by removing or adjusting the filter.

## What was done

Proposed a change to `models/staging/stg_orders.sql`. The original model filtered orders to only those with a year before 1998, which caused recent orders to be dropped, breaking freshness and relationship checks. The filter has been removed to include all orders, restoring correct row counts and relationships while keeping the column definitions unchanged.

```diff
--- a/models/staging/stg_orders.sql
+++ b/models/staging/stg_orders.sql
@@ -7,4 +7,4 @@
     o_orderpriority as priority,
     _loaded_at as loaded_at
 from {{ source('raw', 'orders') }}
-where year(o_orderdate) < 1998
+-- Removed erroneous date filter that excluded orders from 1998 onward
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Patch correctly removes the erroneous date filter, restoring missing recent orders and fixing relationship and freshness failures. No masking of data or column changes involved.
