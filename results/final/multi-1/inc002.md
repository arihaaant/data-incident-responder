# Incident inc002

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `model.tpch_warehouse.stg_orders` error: Runtime Error in model stg_orders (models/staging/stg_orders.sql)

## Diagnosis

- **Started at:** `source.raw.orders`, column `o_customer_key`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`, `stg_orders`

**Evidence**

raw.orders table no longer has column o_custkey; it now has o_customer_key. stg_orders model references o_custkey, causing compile error. This is a schema change upstream; fixing by updating stg_orders to use o_customer_key is a lossless rename patch.

## What was done

Proposed a change to `models/staging/stg_orders.sql`. The upstream raw.orders table renamed column o_custkey to o_customer_key. The staging model referenced the old name, causing a compile error. Updated the SELECT to use o_customer_key while preserving the original alias (customer_key) and all other columns unchanged, ensuring lossless rename and maintaining column contracts.

```diff
--- a/models/staging/stg_orders.sql
+++ b/models/staging/stg_orders.sql
@@ -1,6 +1,6 @@
 select
     o_orderkey as order_key,
-    o_custkey as customer_key,
+    o_customer_key as customer_key,
     o_orderstatus as order_status,
     o_totalprice as total_price,
     o_orderdate as order_date,
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix correctly updates the staging model to reference the renamed source column (o_customer_key) while preserving the original alias and other columns. This addresses the compile error caused by the upstream schema change without masking data.
