# Incident inc041

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `unique_stg_orders_order_key` fail (363 rows): Got 363 results, configured to fail if != 0

## Diagnosis

- **Started at:** `model.stg_orders`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`

**Evidence**

stg_orders model selects from raw.orders twice using UNION ALL, duplicating rows where o_orderstatus='P'. This creates 363 duplicate order_key values, causing the unique_stg_orders_order_key check to fail.

<details><summary>1 queries run during the investigation</summary>

```sql
SELECT COUNT(*) AS total_rows, COUNT(DISTINCT order_key) AS distinct_keys FROM raw.orders
```

</details>

## What was done

Proposed a change to `models/staging/stg_orders.sql`. Removed the erroneous UNION ALL that re‑selected rows where `o_orderstatus = 'P'`. The original model duplicated every order with status 'P', causing 363 duplicate `order_key` values and failing the `unique_stg_orders_order_key` check. The corrected model now selects each row exactly once from the `raw.orders` source, preserving the original column list and types while eliminating the duplication.

```diff
--- a/models/staging/stg_orders.sql
+++ b/models/staging/stg_orders.sql
@@ -7,7 +7,3 @@
     o_orderpriority as priority,
     _loaded_at as loaded_at
 from {{ source('raw', 'orders') }}
-union all
-select o_orderkey, o_custkey, o_orderstatus, o_totalprice, o_orderdate, o_orderpriority, _loaded_at
-from {{ source('raw', 'orders') }}
-where o_orderstatus = 'P'
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix removes the erroneous UNION ALL that duplicated rows with status 'P', directly addressing the duplicate order_key issue causing the unique check failure.
