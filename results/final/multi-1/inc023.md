# Incident inc023

**Status:** Escalated to the owner of raw.lineitem. Nothing was changed.

## What broke

- `not_null_stg_lineitem_order_line_id` fail (1550 rows): Got 1550 results, configured to fail if != 0
- `not_null_stg_lineitem_order_key` fail (1550 rows): Got 1550 results, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.lineitem`, column `l_orderkey`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`, `stg_lineitem`

**Evidence**

raw.lineitem has 1550 rows where l_orderkey is NULL (see count query). stg_lineitem builds order_key from l_orderkey and order_line_id via concatenation, so those rows become NULL, causing not_null checks to fail. The issue originates in the source data, not in model logic.

<details><summary>2 queries run during the investigation</summary>

```sql
SELECT COUNT(*) AS total_rows, COUNT(order_line_id) AS non_null_order_line_id, COUNT(order_key) AS non_null_order_key FROM raw.lineitem
```
```sql
SELECT COUNT(*) AS total_rows,
       COUNT(l_orderkey) AS non_null_orderkey,
       COUNT(l_linenumber) AS non_null_linenumber,
       SUM(CASE WHEN l_orderkey IS NULL THEN 1 ELSE 0 END) AS null_orderkey,
       SUM(CASE WHEN l_linenumber IS NULL THEN 1 ELSE 0 END) AS null_linenumber
FROM raw.lineitem
```

</details>

## What was done

No change was made to the warehouse. The data has to be corrected where it comes from.
