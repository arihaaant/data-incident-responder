# Incident inc026

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `not_null_stg_lineitem_extended_price` fail (29778 rows): Got 29778 results, configured to fail if != 0

## Diagnosis

- **Started at:** `model.stg_lineitem`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`

**Evidence**

The not_null test on stg_lineitem_extended_price failed with 29,778 nulls. Raw.lineitem has 29,778 rows where l_returnflag <> 'N', and l_extendedprice is never null. The stg_lineitem model sets extended_price only when l_returnflag = 'N', causing nulls for the other rows. Row counts match upstream, so the problem is the model's conditional logic, not source data. Patch the model to populate extended_price for all rows (or adjust the test).

## What was done

Proposed a change to `models/staging/stg_lineitem.sql`. The not_null test on `extended_price` failed because the model only populated this column when `l_returnflag = 'N'`, resulting in nulls for other rows. Since the source `l_extendedprice` is never null, we can safely assign it directly to `extended_price` for all rows, satisfying the not_null constraint while preserving the original data type.

```diff
--- a/models/staging/stg_lineitem.sql
+++ b/models/staging/stg_lineitem.sql
@@ -5,7 +5,7 @@
     l_partkey as part_key,
     l_suppkey as supplier_key,
     l_quantity as quantity,
-    case when l_returnflag = 'N' then l_extendedprice end as extended_price,
+    l_extendedprice as extended_price,
     l_discount as discount,
     l_tax as tax,
     l_returnflag as return_flag,
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix removes conditional that introduced nulls and correctly maps source l_extendedprice to extended_price for all rows, addressing the root cause without masking data.
