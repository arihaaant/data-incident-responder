# Incident inc009

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `model.tpch_warehouse.stg_lineitem` error: Runtime Error in model stg_lineitem (models/staging/stg_lineitem.sql)

## Diagnosis

- **Started at:** `source.raw.lineitem`, column `l_ship_date`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`, `stg_lineitem`

**Evidence**

stg_lineitem model references l_shipdate, but raw.lineitem table defines l_ship_date. This schema drift causes compile error. Updating the model to use the correct column name fixes it; the issue originates from the source schema change.

## What was done

Proposed a change to `models/staging/stg_lineitem.sql`. The upstream raw.lineitem table renamed two columns: `l_shipdate` -> `l_ship_date` and `l_return_flag` -> `l_returnflag`. The staging model referenced the old names, causing compile errors. Updated the SELECT to use the correct source column names while preserving the model's output column names (`ship_date` and `return_flag`). No other changes were made to keep the schema and types intact.

```diff
--- a/models/staging/stg_lineitem.sql
+++ b/models/staging/stg_lineitem.sql
@@ -9,6 +9,6 @@
     l_discount as discount,
     l_tax as tax,
     l_returnflag as return_flag,
-    l_shipdate as ship_date,
+    l_ship_date as ship_date,
     l_extendedprice * (1 - l_discount) as net_revenue
 from {{ source('raw', 'lineitem') }}
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix correctly updates the model to reference the renamed source column l_ship_date, preserving output schema. No type/format changes involved; rename handling is appropriate.
