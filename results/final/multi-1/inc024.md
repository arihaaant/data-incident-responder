# Incident inc024

**Status:** Escalated to the owner of raw.customer. Nothing was changed.

## What broke

- `not_null_stg_customers_customer_key` fail (60 rows): Got 60 results, configured to fail if != 0
- `relationships_stg_orders_customer_key__customer_key__ref_stg_customers_` fail (600 rows): Got 600 results, configured to fail if != 0

## Diagnosis

- **Started at:** `source.raw.customer`, column `c_custkey`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `dim_customers`, `fct_daily_revenue`, `fct_orders`, `stg_customers`

**Evidence**

raw.customer has 1500 rows with 60 null c_custkey values (checked via COUNT and SUM). stg_customers directly maps c_custkey to customer_key, so those nulls become null primary keys, causing 60 nulls in stg_customers.customer_key (not_null check fails). stg_orders has 600 rows with customer_key values that do not match any non-null customer_key in stg_customers, triggering the relationships test. The issue originates in the source raw.customer table.

<details><summary>1 queries run during the investigation</summary>

```sql
SELECT COUNT(*) AS total_rows, SUM(CASE WHEN c_custkey IS NULL THEN 1 ELSE 0 END) AS null_custkey FROM raw.customer
```

</details>

## What was done

No change was made to the warehouse. The data has to be corrected where it comes from.
