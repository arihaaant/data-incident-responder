# Incident inc007

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `model.tpch_warehouse.stg_lineitem` error: Runtime Error in model stg_lineitem (models/staging/stg_lineitem.sql)

## Diagnosis

- **Started at:** `source.raw.lineitem`, column `l_discount`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`, `stg_lineitem`

**Evidence**

raw.lineitem table no longer has column l_discount; it has l_discount_rate. stg_lineitem model selects l_discount causing binder error. Column rename is upstream schema drift; fix by updating stg_lineitem to reference l_discount_rate.

## What was done

Proposed a change to `models/staging/stg_lineitem.sql`. The upstream raw.lineitem table renamed the discount column from l_discount to l_discount_rate. The staging model still referenced the old name, causing a binder error. Updated the model to select l_discount_rate as discount and used the same column in the net_revenue calculation, preserving the original output column names and types.

```diff
--- a/models/staging/stg_lineitem.sql
+++ b/models/staging/stg_lineitem.sql
@@ -6,9 +6,9 @@
     l_suppkey as supplier_key,
     l_quantity as quantity,
     l_extendedprice as extended_price,
-    l_discount as discount,
+    l_discount_rate as discount,
     l_tax as tax,
     l_returnflag as return_flag,
     l_shipdate as ship_date,
-    l_extendedprice * (1 - l_discount) as net_revenue
+    l_extendedprice * (1 - l_discount_rate) as net_revenue
 from {{ source('raw', 'lineitem') }}
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix correctly updates the model to use the renamed column l_discount_rate, preserving semantics and calculations. No masking or data loss; type unchanged.
