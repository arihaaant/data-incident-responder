## What broke

- `assert_orders_fresh` fail (1 rows): Got 1 result, configured to fail if != 0
- `relationships_stg_lineitem_order_key__order_key__ref_stg_orders_` fail (29165 rows): Got 29165 results, configured to fail if != 0

## Diagnosis

- **Started at:** `model.stg_orders`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`

**Evidence**

raw.orders contains 15000 rows, but staging.stg_orders only 7667 rows. The stg_orders model applies a filter `where o_orderstatus <> 'O'`, which drops all orders with status 'O'. This filter caused many orders to be missing, leading to 29165 orphaned lineitems (relationship test failure) and a freshness failure. The problem is due to the incorrect filter in the stg_orders model, not upstream data.

## What was done

Proposed a change to `models/staging/stg_orders.sql`. Removed the erroneous filter `where o_orderstatus <> 'O'` which was unintentionally dropping orders with status 'O'. This restores the full set of orders, fixing the orphaned lineitem relationship test and freshness check failures while preserving column names and types.

```diff
--- a/models/staging/stg_orders.sql
+++ b/models/staging/stg_orders.sql
@@ -7,4 +7,3 @@

```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix removes the erroneous filter that was dropping orders with status 'O', directly addressing the root cause and restoring missing rows without masking data.
