# Incident inc060

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `assert_orders_fresh` fail (1 rows): Got 1 result, configured to fail if != 0
- `relationships_stg_lineitem_order_key__order_key__ref_stg_orders_` fail (230 rows): Got 230 results, configured to fail if != 0

## Diagnosis

- **Started at:** `model.stg_orders`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`

**Evidence**

raw.orders has 15000 rows, stg_orders only 14941 rows (59 missing). The stg_orders SQL filters out orders with order_date within the last 7 days (where o_orderdate < max(o_orderdate) - interval 7 day). This filter drops recent orders, causing orphaned lineitems (230) and freshness check failure (1 stale row). Raw data shows no orphaned lineitems, so the issue originates from the stg_orders model code.

## What was done

Proposed a change to `models/staging/stg_orders.sql`. Removed the date filter that excluded the most recent 7 days of orders. This restores the missing 59 orders, resolves orphaned lineitem relationships, and fixes the freshness check. No other columns or types were changed.

```diff
--- a/models/staging/stg_orders.sql
+++ b/models/staging/stg_orders.sql
@@ -7,4 +7,3 @@
     o_orderpriority as priority,
     _loaded_at as loaded_at
 from {{ source('raw', 'orders') }}
-where o_orderdate < (select max(o_orderdate) from {{ source('raw', 'orders') }}) - interval 7 day
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix removes the erroneous date filter that caused missing recent orders, directly addressing the root cause without masking data or altering column definitions.
