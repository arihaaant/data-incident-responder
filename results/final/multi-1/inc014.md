# Incident inc014

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `model.tpch_warehouse.stg_parts` error: Runtime Error in model stg_parts (models/staging/stg_parts.sql)

## Diagnosis

- **Started at:** `source.raw.part`, column `p_brand_name`
- **Cause:** data arriving from upstream
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`, `stg_parts`

**Evidence**

stg_parts model references p_brand which no longer exists in raw.part. raw.part columns list shows p_brand_name instead. This is a schema drift due to column rename. Policy: renamed column carries same data, so staging model should be patched to use p_brand_name. Root is source.raw.part.

## What was done

Proposed a change to `models/staging/stg_parts.sql`. The upstream source raw.part renamed the column `p_brand` to `p_brand_name`. The staging model `stg_parts` still referenced the old column, causing a binder error. Updated the SELECT to use `p_brand_name` while preserving the original alias `brand` and keeping all other column mappings unchanged, maintaining the existing column contracts.

```diff
--- a/models/staging/stg_parts.sql
+++ b/models/staging/stg_parts.sql
@@ -1,7 +1,7 @@
 select
     p_partkey as part_key,
     p_name as part_name,
-    p_brand as brand,
+    p_brand_name as brand,
     p_type as part_type,
     p_retailprice as retail_price
 from {{ source('raw', 'part') }}
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix correctly updates the staging model to reference the renamed source column p_brand_name, preserving the original alias and column contracts. No type/format conversion is involved, so lack of profile is acceptable.
