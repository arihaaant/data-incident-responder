**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `not_null_fct_orders_region_name` fail (14744 rows): Got 14744 results, configured to fail if != 0

## Diagnosis

- **Started at:** `model.dim_customers`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`, `fct_orders`

**Evidence**

fct_orders has 14,744 null region_name out of 15,000 rows. dim_customers has only 24 rows, all non-null region_name. The join in dim_customers uses c.customer_key = n.nation_key, which is incorrect, causing most customers to be dropped. Correct join should be c.nation_key = n.nation_key and use left joins to retain all customers, fixing the null spike.

## What was done

Proposed a change to `models/marts/dim_customers.sql`. Fixed the join logic in dim_customers. The original join incorrectly matched c.customer_key to n.nation_key, dropping most customers and causing downstream null region_name values. Updated to join on the correct foreign key c.nation_key = n.nation_key and changed the region join to a left join to retain all customers even if a region is missing. This preserves column names/types and ensures all customers appear in the dimension, addressing the null spike in fct_orders.region_name.

```diff
--- a/models/marts/dim_customers.sql
+++ b/models/marts/dim_customers.sql
@@ -6,5 +6,5 @@
     n.nation_name,
     r.region_name
 from {{ ref('stg_customers') }} c
-left join {{ ref('stg_nations') }} n on c.customer_key = n.nation_key
-join {{ ref('stg_regions') }} r on n.region_key = r.region_key
+left join {{ ref('stg_nations') }} n on c.nation_key = n.nation_key
+left join {{ ref('stg_regions') }} r on n.region_key = r.region_key
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix corrects join key and uses left joins, restoring all customers and eliminating null region_name spikes. No masking or data alteration.
