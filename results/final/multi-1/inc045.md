# Incident inc045

**Status:** Fix proposed. Needs a human review before it is merged.

## What broke

- `unique_stg_lineitem_order_line_id` fail (14902 rows): Got 14902 results, configured to fail if != 0

## Diagnosis

- **Started at:** `model.stg_lineitem`
- **Cause:** a change in a model
- **Downstream models affected:** `fct_daily_revenue`, `fct_order_items`, `fct_orders`

**Evidence**

stg_lineitem model unions raw.lineitem with itself (all rows + rows where l_returnflag='R'), creating duplicate order_line_id values. Raw.lineitem has 60,175 rows and no order_line_id column; duplicates arise in staging. The uniqueness check on stg_lineitem.order_line_id reports 14,902 duplicate rows, matching the extra rows from the union. Fix by removing the UNION ALL or correcting intended logic.

<details><summary>2 queries run during the investigation</summary>

```sql
SELECT COUNT(*) AS total_rows FROM raw.lineitem
```
```sql
SELECT COUNT(DISTINCT order_line_id) AS distinct_ids FROM raw.lineitem
```

</details>

## What was done

Proposed a change to `models/staging/stg_lineitem.sql`. Removed the erroneous UNION ALL that duplicated every row and added a filtered subset, which caused duplicate order_line_id values and broke the uniqueness check. The model now selects each lineitem exactly once, preserving the original column definitions and types.

```diff
--- a/models/staging/stg_lineitem.sql
+++ b/models/staging/stg_lineitem.sql
@@ -12,7 +12,3 @@
```

- **Tested in a copy of the warehouse:** every check passed.
- **Reviewer:** approved. Fix removes the erroneous UNION ALL that duplicated rows, eliminating duplicate order_line_id values and satisfying the uniqueness check. No masking or data loss; aligns with root cause.
